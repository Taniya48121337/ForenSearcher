# ForenSearcher 全面漏洞审查（2026-09-24）

范围：整体 idea（DESIGN.md）、训练方案（09-11）、SFT 数据构造 v2（09-21）、第 0 轮数据（09-21/23）、RSI 融入方案（09-24）、待删除清单（09-24），以及对应代码。做法：我自己过一遍，另派两个互相独立的审查——一个按顶会审稿人的标准挑方法和实验，一个逐条核对文档、代码、方案之间的矛盾——再逐条复核后合并。复核时推翻了的说法不列入。

结论先说：**骨架站得住**。领域有外部参照（数据集标签、原始来源、案卷），双角色能按输入归因，规格已版本化，这三点是真正的支点。但有 **4 个会让论文站不住的漏洞**、**9 个严重问题**、若干中小问题，其中几处是我前两轮回答里说错了的，第 0 节先更正。

## 1. 致命级（不修，论文站不住）

### F1. "真值核验器"名不副实，校准有循环

- **现状**：只有数据集标签是真值；过程判定的第二、三层是 LLM（qwen3.8-27b，reasoning low）。召回只在 1 个 run 上测了 19 次注入，drop_required_finding 0/4；step / plan / answer 单元没有召回校准；按错误类型的人工精确率一条都没有。
- **循环**：R1、R2、R4 三条校准规则全是放宽方向，而且都是为了让 true:4124903 这一个 run 里的某一行通过而写的，再用这个 run 的结果说明校准有效。这正是方案 §4.5 担心的"核验器越改越松"，只是发生在冻结参考核验器之前。
- **两个衍生问题**：
  - 核验模型走 OpenRouter 托管，权重可能被静默更换，"冻结 verifier_ref"做不到。
  - verifier_ref 与训练用核验器同一个模型，两者犯的错相关，所以 exploitation rate 测不出真正的钻空子。
- **修补**：
  1. 措辞从"真值核验"改为"**以外部参考材料为锚的核验**"：标签、原始来源、案卷是锚，LLM 是执行者。
  2. 建人工金标集：≥300 对 (Finding, E)，加 ≥100 个 step/plan/answer 单元，按错误类型分层，两人标注，报 κ 和置信区间。这是第①步阈值能被检验的前提。
  3. 校准规则一律先登记、再在**另外的** run 上测假接受率，不在推导出它的 run 上验收。
  4. 核验器改为本地固定权重。verifier_ref 用与教师、训练用核验器都不同家族的模型，外加人工抽检；exploitation rate 只以人工判定为准。

### F2. 路由器的判据没有被独立验证，E4 是循环论证

- **判据本身**：t≈s 时外环（教师桥接、拒绝采样）同样能修；s≫t 也可能只是学生读不懂提示，内环改手册同样能修。所以"教师–学生差距"既不必要也不充分。两个阈值条件可以同时成立，文中没说哪个优先。另外，教师比学生多拿一段 teacher_instruction，"同规格"并不是同一份输入。
- **E4**："能力缺陷"是只微调学生注入的，教师按构造一定不犯，所以必然路由到外环。这个测试只证明路由器能认出为它量身设计的缺陷。
- **修补**：
  1. 路由器降为**先验**。对每轮前 3 格错误做小预算的**双干预**：一个内环候选，加一次针对该错误的小规模 LoRA 增量训练；实测哪根杠杆降错多，把它作为该格的反事实最优杠杆。
  2. 贡献改写成可测量的量：**先验判据预测反事实最优杠杆的准确率**。
  3. 教师率 t 用"教师只拿 student_prompt、不拿 teacher_instruction"的探针在小样本上测，保证输入相同。
  4. 两个条件的优先级写死：先看 s−t，再看 t。
  5. E4 的缺陷由项目外的人盲设计，混入两根杠杆都能修的模糊缺陷；正确答案由上面的双干预决定，不由设计者声明。

### F3. 规模与可行性差一个数量级

- **案卷**：现在 1 份，计划 10–12 份；方案的功效估计要求每个划分约 150 对案例，还要切成 4–5 个划分。案卷是人（或 LLM 加人）逐份写的，这是最大瓶颈。
- **算力**：122B BF16 占满 8 卡，和学生采样、训练、媒体工具互斥。E1 四臂 × 4 轮 × 2–3 个 LoRA 种子 × 每案例 2 个推理种子，再加 3×3 交叉矩阵、4 个执行模型迁移、E6、E7，每轮还有教师陪跑、提议者调用、核验调用。没有任何一项有实测的单案例成本。
- **修补**：
  1. 先做一次**成本实测**：5 个案例 × {教师、学生、核验、工具}，量单案例的 GPU 分钟、token、墙钟时间，再定臂数和轮数。
  2. 案卷生成自动化：从 TRUE 的核查理由、AVeriTeC/AVerImaTeC 的证据 QA 自动起草 requirements / required_evidence，人工只做审核，并量出每份的人工分钟数。
  3. 教师用 FP8 版 122B，只占 4 卡。
  4. 按实测结果裁剪到"最小可发表集"（第 9 节）。

### F4. 开放网络：跨轮漂移与测试污染

- **漂移**：ddgs 的搜索结果、网页内容随时间变化，跨轮、跨臂的曲线里混着环境变化，分不开。
- **污染**：TRUE、EVID 的核查文章能直接搜到，第 0 轮就引用了 Snopes。模型可能学成"找现成核查文章"。"真实来源优先"目前只是一句话，没有执行机制。
- **修补**：
  1. **检索录制回放**：每个案例第一次运行时录下搜索结果、打开的页面、下载的媒体；dev_select、dev_confirm、dev_eval、test 上的所有臂和轮次都用同一份快照。
  2. 检索结果按声明日期截断。
  3. 核查站点域名黑名单，测试时报告"带黑名单 / 不带黑名单"两组结果，并统计每个 run 命中核查站点的比例。
  4. OCR、ASR、对齐这类工具结果也做缓存，并报告重跑方差。

## 2. 严重级

### S1. "递归"和"自我"两个词难以成立

提议者是教师，修补靠教师桥接，判定靠另一个 LLM。自指消融写着"做不成不影响主线"，等于承认主线不递归。审稿人会把它归为"ReST/STaR + 提示优化 + 教师蒸馏"。更关键的是**缺一个对照臂**：用同样的教师 token 和 GPU，教师直接多产数据蒸馏、不跑循环。

**修补**：
- 补"纯蒸馏"臂，并把增益拆分到教师 token 与学生自采两部分。
- 主线里必须有一个真正递归的环节做成、不做成就不称 RSI。候选：第 2 轮起入选数据中学生自采占 ≥50% 且留出集不降（教师依赖率曲线）；或学生 GIA 当提议者的质量随轮次上升。
- 否则标题改成"核验路由的有界自我改进"。这一条需要拍板。

### S2. 门控统计

- **赢家诅咒**：K=4 个候选取最好的，却没有噪声基线。
- **多重比较**：3 格错误 × K 个候选 × 3 条接受条件，没有校正。
- **合并未复检**：多个接受的改动合并成 spec@n+1 后没有再过门。
- **门 A 对学生侧改动不公平**：student_prompt 类改动由"在旧提示下训出的学生"评估，属于分布外评测，会被系统性低估。
- **曲线天然单调**：回滚机制让画在门控集上的曲线天生不降，这是选择偏差。

**修补**：
- 先做 **A/A 测试**（同一规格对自己）量出门的假接受率。
- **每轮最多只让 1 个规格改动进入下一版**：选出的最优者再在 dev_confirm 上确认，确认结果参与决策。这同时回到 v2 §10 的"每轮只改一样"。
- 预先登记 α，并做 Holm 校正。
- student_prompt、手册类改动走"暂定接受 → 下一轮重训后由门 B 定夺"。
- 所有曲线只画在**从未参与决策**的 dev_eval 与 test 上。

### S3. 两个模型互造数据

- **通道 2 输入问题**：它给 GIA 加了部署时没有的输入（HI 薄弱点）。这违反 DESIGN §2.3"全局视图固定五块"；如果这些输出进了 GIA 的训练集，还会造成训练/部署不一致。
- **门 B 无法定位**：它把 HI 和 GIA 两次更新合在一起比较，过不了门时不知道该回滚哪个。
- **协同项没有置信区间**：它是 2×2 的单点估计，而交互项方差大约是主效应的两倍。
- **通道 3 在漂**：学生 HI 变好后烂报告变少，GIA 的恢复样本分布会一直变。

**修补**：
- 课程任务只作为 HI 的训练输入，打上 origin=curriculum 标记，**永不进 GIA 的训练行**；在 HI 数据里的占比封顶 30%。
- 门 B 拆成 B-HI、B-GIA 两道。
- 交叉矩阵跑多种子并给置信区间。
- 通道 3 固定混入一定比例的教师报告和旧版 HI 报告。

### S4. 奖励黑客路径（学生自采 + LLM 核验筛选）

学生会被推向"讨核验器喜欢"的写法，具体路径有：
- 少写、写含糊的 Finding（"与报道相容"）；
- 堆引用，触发 R1 范围豁免、R4 兄弟证据覆盖；
- R2 降级后不传播污染；
- 过度报 INCOMPLETE；
- GIA 派容易的任务（通道 2 的"成功率居中"筛选加上 round_yield 都在鼓励这一点）。

**修补**：
- 加信息量指标：每项必需要求被 supported Finding 覆盖的比例、每个工作区的有效 Finding 数。
- 可回答案例上的 INCOMPLETE 率设上限，逐轮报告。
- 每条校准规则都配"不该被豁免"的反例注入，测它的假接受率。
- 建一个对抗探针集，专门测上述几条路径。

### S5. 调查手册会泄漏 dev 事实，或变成数据集专用规则

提议者读 dev 的成败轨迹写条目，条目可能带上具体事件，比如"耶拿桥卡车起火"，或写成 TRUE/EVID 专用的启发式，违反 DESIGN §6 第 16 条。TRUE 的 dev 和 test 同源，存在事件级泄漏风险。

**修补**：
- 程序拦截含实体、数字、URL、日期的条目。
- 条目与 test 做 n-gram 审计。
- 手册的收益只在留出数据集上宣称。

### S6. 内环的可改对象与既定设计冲突，部分根本不存在

- **"接口契约"可演化**：给 GIA 任务加"目标要求 / 禁止前提"字段，等于把 task 拆成多字段（DESIGN §6 第 13 条）；HI 报告加"未完成原因"会滑向 unresolved 列表（第 18、19 条）；而且必须改解析代码，与"不改代码"矛盾。
- **state_renderer 可演化**：违反 v2 §10"渲染档位整个实验期不变"。另外本地配置用 compact_8k、服务器用 compact_16k，第 0 轮导出用 8k，与"只出部署档"不一致。
- **harness_params 没接上**：规格里的 harness_params 目前只记录、运行时不读（代码重构记录 §四）。
- **Harness-1 机制还没做**：精选集、指纹去重、句子压缩三个机制尚未移植，它们的参数现在无从演化。
- **两处隐患**：移植后，focus 的重要性必须由 HI 判定（第 10 条）；去重不能合并不同来源的转载（转载本身是溯源证据）。
- **修补**：
  - 删掉"接口契约"这个可演化对象，改成 GIA student_prompt 里"如何写任务"的文字指导，task 仍是一个字段。
  - state_renderer 移出白名单，全项目统一一个档位（需拍板：8k 还是 16k）。
  - 先让运行时从规格读参数，才允许内环改 harness_params；改动会影响学生输入分布的参数升 minor，不是 patch。
  - Harness-1 机制参数在移植完成前不进白名单。

### S7. 教师切换与付费 API

第 0 轮所有数据、账本、"教师率"都来自 gpt-6-astra（API），主线教师却是 Qwen3.5-122B。09-11 方案写"不开付费 API"，核验器却走 OpenRouter。

**修补**：
- 定下一个教师（122B FP8），用它重做 r0。gpt-6-astra 数据只作流水线验证，不进正式训练。用闭源模型输出训练模型还要先核对其服务条款。
- 核验器本地化（见 F1）。

### S8. E5 相关性分析功效不足

4 轮大约 20 个点，彼此不独立，而且只取了过门的改动，存在范围限制。ρ 的置信区间大概率覆盖 0，"正面回答 S³Gym"会落空。

**修补**：用冻结权重的内环专门生成 100–200 个随机或扰动的规格改动（包括明显变坏的），做剂量–反应分析，用分层模型并按轮次、种子聚类。内环不训练，这个成本可以接受。

### S9. 数据复习规则与 spec_hash 规则冲突

v2 §10 规定 spec_hash 不同的数据不能混训，而训练方案要求每轮 80% 复习 r0 数据。

**修补**：复习数据用当前规格从 run 日志**重新导出**。export 本来就是按日志现场渲染，所以可行。只保留在当前核验器下仍为 positive、且与当前手册条目不冲突的行。

## 4. 新颖性风险

- Co-Harness 已经做了"把 agent_error 排除在 harness 修复之外"，这是我们路由第③步的核心。
- Harness-Zero 在同一个 Qwen3.5-9B 上做了内化。
- RHI 做了多智能体契约演化。
- Agent0、SAGE、MAE 做了多模型共同演化加外部核验。

"Co-Harness 把多智能体列为未来工作"这句是从工具摘要里得到的，引用前要逐字核对原文。S³Gym 的 ρ≈−0.01 来自 09-15 的内部记录，也要回原文核对。

**修补**：差异点落到**别人没有测过的量**上：
1. 反事实最优杠杆的预测准确率（F2）；
2. 跨角色错误传播的归因准确率（用植入的上游错误测 origin_role 判得对不对）；
3. 核验分–提升的剂量–反应曲线（S8）。

再准备一个**领域贡献**作第二支点：带过程级核验标注的视频核查轨迹数据集，即案卷 + verdicts + 轨迹。这也是 DESIGN §8 退路的具体化。
