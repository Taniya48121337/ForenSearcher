# ForenSearcher 双模型联合自进化训练方案

设计日期：2026-09-11。适用资源：8 × 80 GB A100；本地 Qwen 235B 与训练共用同一台机器。本文给出训练设计、数据规范与起始配置，尚未完成正式数据构造或训练；配额、阈值与超参数均需用小规模运行校准。

## 1. 方法与训练对象

训练主线：**证据支撑的任务 rubric → 真实执行与对照轨迹 → 按角色逐决策 SFT → 带过程奖励的交替 REINFORCE++ 训练 → 根据已核实错误更新数据、rubric 和通用操作提示。**

Rubric 是一份具体的评分清单：说明这道题需要证明什么、什么证据足以证明、哪些推断不成立，以及应评价哪个角色的哪次决策。它不是预先写好的唯一调查路线，也不改变运行时的任务类型。

| 对象 | 建议配置 | 学习内容 |
|---|---|---|
| GIA | Qwen3-8B，独立 LoRA | 动态分工、轮次安排、综合报告与证据、继续调查或结束 |
| HI | Qwen3-8B，独立 LoRA；全部 Workspace 共享 | 搜索、媒体检查、证据使用、局部报告与停止 |
| Qwen 235B | 保持参数不变，分时加载 | 整理参考材料、生成示范、提出 rubric、审核训练数据 |
| 现有视觉、音频与检索工具 | 沿用工程工具 | 执行 SEARCH、INSPECT 等观察与检索 |

Qwen3-8B 的原生上下文为 32K；采用两个 8B 策略是为了为长上下文、轨迹采样和工具运行保留资源，不代表已经证明其优于所有更新模型。[模型卡](https://huggingface.co/Qwen/Qwen3-8B)

联合训练采用交替协同后训练：两者共同执行调查，一次优化只更新一个角色，更新搭档后重新采样。没有跨两个模型的普通端到端反向传播，也不新增可训练的价值模型或正式运行角色。

保持现有调查语义：GIA 创建 Workspace，轮内并行、轮间串行；E 保存完整后在本次调查共享，HI 每次行动前获得当时的证据视图；HI 不读取其他 Workspace 的 Finding 或报告；E 是来源或工具观察，F 是有证据引用的解释。训练分支相互独立。

## 2. 研究依据与适配边界

| 研究 | 采用的思想 | 对本任务的适配边界 |
|---|---|---|
| Harness-1 | 教师实际运行；同一状态呈现方式；逐轮 SFT；区分发现证据与最终选择 | 单个检索策略的奖励不能直接给 GIA；默认 RL 不是逐动作 rubric 奖励 |
| DR Tulu / RLER | 利用检索材料和不同回答生成、更新具体 rubric | 采用训练轮次之间的更新，降低本地 235B 的反复加载成本；固定事实要求不会因容易满足而删除 |
| SRaR | 从正确与错误路径对照提炼 rubric；反馈定位到具体步骤 | 原实验是数学推理；不把不同 Workspace 的相同步号视为同一状态 |
| Robust Rubric Rewards | 可以程序验证的条件用程序，其余用有参考材料的判断 | 引用编号存在不代表语义支持；视觉真值不能由文本教师凭空推断 |
| MAPPA | 根据角色、输入和实际反馈检查动作；无 Critic 的过程 RL | 采用角色分别归一化和交替更新；模型评价仍不是严格因果归因 |

来源：[Harness-1](https://arxiv.org/html/2606.02373)、[DR Tulu](https://arxiv.org/html/2511.19399)、[SRaR](https://arxiv.org/html/2605.17291)、[Robust Rubric Rewards](https://arxiv.org/html/2605.30244)、[MAPPA](https://arxiv.org/html/2601.23228)。

近期 AudioRubrics 将评分标准与原始音频联系起来，对音频替换核查有参考价值。但它需要具备音频能力的评估模型；文本 Qwen 235B 不能仅凭转录判断配乐、说话人或声画对应关系。[AudioRubrics](https://arxiv.org/html/2608.02831)

Rubric 的质量需要单独验证。相关研究区分了两类失败：评分器没有正确执行标准，以及标准本身遗漏了重要错误。增加一个更大的裁判不能自动解决第二类问题。[Reward Hacking in Rubric-Based RL](https://arxiv.org/html/2605.12474)

## 3. 数据来源与划分

### 3.1 首批原始案例

首批目标为 1,000 条原始案例，先做其中 100 条测量可行性。以下是选择配额，不是已经取得的合格数据量。

| 来源 | 首批配额 | 采用的内容 | 训练目的 |
|---|---:|---|---|
| TRUE | 500 | 视频、声明、原始核查理由与来源 | 视频来源、时间、语境和事实核查 |
| AVerImaTeC | 200 | 图文声明、证据 QA、来源图片和网页 | 图像溯源、图文关系、跨来源核对 |
| AVeriTeC | 200 | 声明、证据 QA、来源与结论 | 全局拆题、文本证据、冲突与证据不足 |
| VideoSham | 100 对素材案例 | 原片、修改版本、编辑说明与源视频链接 | 对应片段、可见修改、时间变化和音频变化 |

TRUE 提供原始理由与 LLM 总结两种材料，并包含证据字段。使用原始理由和实际来源构造参考依据；LLM 总结、自动转录和自动关系标注只作辅助。[TRUE 数据说明](https://github.com/MeiTaylor/TRUE-3MFact/blob/main/TRUE_Dataset/TRUE_Dataset.md)

AVerImaTeC 和 AVeriTeC 的证据 QA 适合整理成局部问题与评分依据，但不强制 GIA 逐字采用原始 QA 分解。保留 Supported、Refuted、Not Enough Evidence、Conflicting Evidence 等任务语义；不把全部任务简单改成二分类。[AVerImaTeC](https://fever.ai/dataset/averimatec.html)、[AVeriTeC](https://fever.ai/dataset/averitec.html)

VideoSham 发布 352 对原始/修改视频及六类编辑说明。第一阶段主要用于“给定待查素材和匿名候选素材”的局部比对训练；它不直接证明开放网页溯源能力。CSV 中有些时间指向原始长视频，必须与发布的短片核对，不能直接当作短片定位真值。[数据与下载](https://github.com/adobe-research/VideoSham-dataset)、[编辑元数据](https://raw.githubusercontent.com/adobe-research/VideoSham-dataset/main/VideoSourceandEdits.csv)

所有给模型看的路径、素材名称和元数据都避免携带 Processed、Unedited、真假标签或编辑说明。它们只进入训练侧参考材料。原片作为候选给出时，按该条件生成和报告结果。

后续 RL 使用通过材料检查的训练池，按约 50% TRUE、20% AVerImaTeC、20% AVeriTeC、10% VideoSham 抽样；可用量不足时报告实际分布，不拿重复改写冒充新增案例。

### 3.2 划分规则

在改写问题、制作对照条件和生成轨迹之前完成划分。

- TRUE：保留官方 test；从 train_val 按事件分组留出 300 条开发案例，其余进入候选训练池。
- AVerImaTeC、AVeriTeC：使用官方 train 训练，官方 dev 开发。明确使用的发布版本，避免把不同版本中重复案例当作新增数据。
- VideoSham：按共同源视频及插入素材的关联分组，目标比例 70%/15%/15%；一个源视频及其全部修改后代进入同一划分。分组后数量以实际统计为准。
- 相同视频、事件、近重复声明、同一核查文章派生案例跨数据集检查；发现与测试重合时剔除对应训练材料，不把测试移入训练。
- 同一家族的完整证据条件、证据缺失条件、干扰条件和语言改写不跨划分。

TRUE 的 300 条开发案例分为两组：150 条用于 rubric、数据规则和提示开发，150 条用于模型轮次与超参数选择。开发案例的具体答案和修正轨迹不进入参数训练。

### 3.3 测试

主测试采用 TRUE 官方 test 与 EVID-Bench。EVID-Bench 有 222 个样本，针对依靠外部视频证据才能核验的误导，适合检查来源搜索和跨视频分析。[EVID-Bench](https://arxiv.org/html/2606.04098)

辅助测试采用 VideoSham 自行划分的保留源视频，以及 AVerImaTeC 官方测试协议。若官方测试答案不可访问，使用官方评测渠道；不能把公开开发集写成独立盲测结果。

报告最终结论指标、关键事实覆盖、引用支持精度、错误停止率、工具和 token 成本。只有具备经过核对的位置标注时才报告片段定位指标。EVID 采用其 point-level 和 video-level 等正式评价项，检查具体误导点是否解释正确，不能用“全部判假”的准确率代替调查质量。测试时同样区分开放网页检索与给定候选素材。

## 4. 一条训练案例需要什么

训练案例包含四部分：

1. **模型输入**：用户问题、用户提供的素材，以及该任务正常允许提供的初始材料。
2. **训练侧参考材料**：标准结论、核查原文、可验证的来源内容、关键视频/音频片段、允许的等价依据。
3. **训练侧 rubric**：全局要求、局部任务适用要求、证据支持规则和具体错误类型。
4. **真实执行轨迹**：各角色实际输入、行动、工具结果、证据可见性、报告及 token 记录。

参考材料中的 ID 与运行时 E 编号分开。轨迹评分时依据来源和内容位置，把真实获得的 E 对应到参考材料；不能预先把金标准来源登记到演员的证据库。

### 4.1 先整理证据，再生成标准

对每道题，先从原始标注抽取：待核查的关键命题、支持或反驳材料、材料适用范围、原始位置、仍无法证明的内容。

例如，核查“这段视频是否在某次近期事件拍摄”时，参考材料可能只足以证明：同一段画面在更早时已发布。它可以反驳近期首次拍摄的说法，但未必能给出准确拍摄日期或地点。

来源打不开时按可用材料处理：已有发布快照可读则使用并保留获取信息；只剩一段无法核实的二手结论时，不生成强过程标签。还保留真实网页来源优先于案例核查文章的证据链，避免训练只剩查找现成核查答案。

### 4.2 Rubric 写成原子条件

每题起始约 6–10 个事实/结果条件，另按角色调用少量通用过程规则。相同事实的多个表述合并，避免通过把一条标准拆成十条改变总分。

| 字段 | 含义 |
|---|---|
| criterion_id | 普通训练记录主键 |
| scope | HI 行动、HI 报告、GIA 决策、GIA 轮次或 GIA 最终回答 |
| criterion | 单一、具体、可检查的要求 |
| applies_when | 当前任务或当前信息下何时适用 |
| reference | 评分参考材料及精确位置，演员不可见 |
| verifier | 程序检查、材料支持判断或人工媒体复核 |
| dependencies | 需要共同成立的前提；允许多种等价证据路径 |
| importance | 必要事实或辅助事实，起始权重分别 2 和 1 |
| failure | 可直接判定该项失败的情况 |

“相关视频一致且发布时间早于声明事件”应拆成两个条件，再用 AND 表达它们共同支持结论。多个可靠来源可以各自支持同一个条件，以 OR 接受等价路径，不要求命中唯一 URL。

初始权重由统一规则设置，不让模型随意为每题发明权重。必要事实优先；语言华丽、篇幅、工具种类数量和反思措辞不计分。

### 4.3 示例 rubric

以下仅为方法示例，不是已核验的真实案例。

| 条件 | 评价对象/边界 | 判断依据 |
|---|---|---|
| 取得候选来源的可读内容与发布日期 | 来源调查 HI 的相关行动 | 实际来源内容；区分发布时间字段与其他日期 |
| 证明候选素材与待查视频的关键片段对应 | 比对 HI 的相关行动与报告 | 已核对的画面或片段对应，不只看相似背景 |
| 早期来源日期确实早于声明中的事件时间 | 来源 HI 报告；GIA 综合 | 可解析日期与任务时间要求 |
| 结论同时依赖来源时间和同素材关系 | GIA 最终回答 | 两项必要条件共同成立，并能沿 E 回到依据 |
| 不把上传日期写成精确拍摄日期 | 实际作出该断言的 HI/GIA 决策 | 引用材料的支持范围 |
| 素材尚未对应时不提前结束核查 | GIA 停止决策 | 决策时可见状态与尚缺的必要条件 |

GIA 的计划不要求直接知道参考答案。计划质量按当时可见的缺口评价；后续事实用于评估执行效果，不能倒推要求它一开始就知道隐藏来源。

## 5. 高质量数据构造流程

### 5.1 材料整理与首轮人工校准

从首批案例中选 60 条：30 TRUE、10 AVerImaTeC、10 AVeriTeC、10 VideoSham。人工查看关键来源、原媒体与 rubric，优先发现上传/拍摄时间混淆、不同素材误匹配、合成类别过度归因等错误。

这些案例可以属于训练集，承担标注方法的校准。另从开发集抽取决策和报告检查评分一致性，不将开发轨迹加入训练。

可交给程序检查：参数格式、实际执行、引用是否存在、来源日期字段比较、已核对的片段区间比较。需要理解材料含义的判断，由 235B 基于实际材料提出结论。重要视觉或音频事实需要人工复核；同一模型换提示、换随机种子得到一致结果不算独立验证。

### 5.2 Rubric 生成与检查

给 235B 的 rubric 生成输入是任务、已经整理的参考材料及角色边界，要求：

- 每项只判断一件事，指明证据位置和适用条件。
- 只写能由参考材料支持的要求，不补出缺失的日期、地点、作者或编辑原因。
- 同时覆盖必要事实与典型误推断。
- 接受等价来源和不同调查路线。
- 不要求提到评分标准本身，不奖励“我已核实”等自我声明。

再检查 rubric 能否区分四类诊断回答：正确且有依据；结论正确但引用错误；引用正确但作出过度推断；准确指出材料不足。诊断回答只用于测试评分器，不能冒充实际执行轨迹。

评价程序抽取演员写出的事实值时，不向抽取步骤提供待比较的标准值；语义支持判断则必须提供被引用材料。程序只验证真正可计算的值，不把“模型说支持”包装成确定性验证。

### 5.3 教师真实执行

每题先运行一条 235B 双角色示范。使用正常输入和现有 SEARCH/INSPECT，不把答案、参考来源清单或题目特定 rubric 展示给执行者。

对失败、单一路径或有争议的案例再采样一条。首批最多约 2,000 条完整尝试；通过率由实测决定。可以使用通用策略提示增加探索差异，但不能加入只从参考答案得知的事实。

中途修正后需要重新执行后缀。工具 Observation、E 和报告均来自实际运行，不能根据标准答案补写一段“当时找到了某网页”的记录。

### 5.4 对照轨迹提炼 rubric

SFT 学生可用后，从同题采样两条学生轨迹，与教师轨迹对照。依照事实正确性和证据支持将差异定位到具体行动，而不只按最终标签分组。

保留四类情况：最终成功且过程合理；最终成功但中间有错；最终失败但部分行动有效；最终失败且过程也有问题。

235B 从已经核实的差异提出最多 2–3 条补充标准。例如，学生反复把转载时间当作事件时间，补充“使用的是哪一种日期、能支持什么结论”。新标准需回到参考材料核验，并在新的轨迹上检查区分能力，不能仅为让某条既有答案获胜而编写。

这一做法借鉴 SRaR 的对照提炼和 DR Tulu 的检索支撑标准更新。应用到视频调查后，来源内容与媒体对应关系成为额外的核验依据，而不是只用答案匹配区分好坏。

### 5.5 证据条件对照

从约 200 个训练案例各选择一个条件变体，优先覆盖停止与证据使用错误。至少保留以下几种真实可执行的变化：

| 变化 | 实际操作 | 期望学习的能力 |
|---|---|---|
| 候选近似但不同源 | 在候选集合中加入真实、相似而不对应的素材 | 不因画面相似就判定同源 |
| 关键来源不可访问 | 在隔离的材料集合中移除来源及其可识别副本 | 区分事实真值与当前可证明范围，补查或准确报告不足 |
| 来源可访问但证据尚未读入 | 保留来源可检索，移除预提供提示 | 自主找到并检查证据，不能把尚未读取视为永久缺失 |
| 有素材对应但缺乏日期依据 | 保留原片对照，不提供未经证实的时间信息 | 比对成立不自动意味着时间归因成立 |
| 前提已被证据否定 | 从实际获得反证的状态继续运行 | GIA 改变调查方向，HI 准确指出前提问题 |

证据被移除不改变现实真值；改变的是可回答性和行动要求。如果其他来源仍足以作答，就不能把它标成证据不足。完全限制来源集合的条件明确标为材料受限训练，与开放网页训练分开记录。

这些变体不伪造搜索返回，不在开放网页环境中假称某个事实不存在。条件变化后，由模型重新实际执行；同一家族全部保留在原划分中。

### 5.6 局部任务与局部 rubric

GIA 运行时仍自主拆题。训练侧在评分时，根据该 Workspace 的实际任务、创建时的输入和全局参考材料，确定局部适用事实。映射先于评分该 HI 输出，不从 HI 的回答倒推一个方便满足的目标。

原始证据 QA 可作为对照，但不机械一问一 Workspace。来源 HI 不因没有完成音频比较而扣分，声音比对 HI 不因没有搜索事件地点而扣分。

前提错误或当前工具不可完成的任务，允许 HI 以证据指出问题；训练目标不能强迫它产出不可获得的答案。对于实际无法评分的动态子任务，保留轨迹供人工/教师复核，不以全局真假标签替代其局部标注。

### 5.7 数据输出与抽样

每个实际决策都检查。纯机械项自动处理；语义项仅向评分调用提供该决策所需的实际材料。判断动作选择是否合理时不提供未来证据；对实际事实陈述的核验可以使用参考材料，但区分“客观错误”和“当时可识别的决策错误”。

输出包括：适用 rubric、满足/不满足/不适用/无法确认、实际行动位置、证据位置和简短理由。无法确认不等于不满足。

- SFT：接受当时输入下可执行且有依据的行动和报告。
- RL：保留当前策略实际采样的好与坏轨迹；不能只保留成功样本做在线策略梯度。
- 关键事实或终止结果无法可靠评分的 episode：暂不用于 RL，其可靠局部决策仍可用于 SFT。
- 修复数据：同一状态下生成可达的替代动作，执行验证后加入后续 SFT；验证失败的不充当正例。

抽样单位按案例、Workspace、决策依次组织，避免一条超长轨迹或创建很多 Workspace 的案例支配训练。真假、证据不足、冲突、媒体比对和错误恢复都需要覆盖；配额不改变正式任务定义。

## 6. 两个角色的奖励

以下系数是起始实验设置，不是论文已验证的最优值。格式合法不发正奖励；通过实际运行保存的事实与证据才可能带来正分。

### 6.1 HI 的局部报告奖励

对 Workspace w 定义：

- C_H(w)：局部任务中必须回答的事实或必须说明的限制，正确完成的加权比例，取值 0–1。
- S_H(w)：报告关键断言被实际引用 E 支持的加权比例，取值 0–1；空报告不获得支持满分。
- U_H(w)：报告含可核实的关键虚构、关键错误断言或决定性过度推断时为 1，否则为 0。无法核验的情况不自动判为 1。

局部报告奖励：

    Q_H(w) = C_H(w) × (0.5 + 0.5 × S_H(w)) − U_H(w)

任务本身要求核验可获得范围时，充分说明哪些材料已检查、什么事实可成立、什么仍不能证明，可以正确完成相应局部要求。单独输出“不知道”不算完成。COMPLETED/INCOMPLETE 字样不直接决定分数。

Q_H 属于 HI，在该 Workspace 的报告决策处加入。GIA 最终答错不直接改写 Q_H；若 HI 报告本身正确，应保留其局部评价。

### 6.2 GIA 的最终奖励

- C_G：最终主要结论符合任务参考结论的程度。有明确类别时先按该类别核对；开放式多项任务按必要结论逐项判断。
- S_G：必要证据条件覆盖 K_G 与最终关键断言引用支持精度 P_G 的调和平均，即 2 × K_G × P_G / (K_G + P_G)；分母为零时取 0。K_G 按必要条件权重计算，P_G 按最终关键断言权重计算。需要同素材关系和日期共同成立的条件必须共同满足。
- U_G：最终回答存在可核实的关键虚构、关键错误或决定性过度推断时为 1，否则为 0。

    Q_G = C_G × (0.5 + 0.5 × S_G) − U_G

Q_G 在 GIA 的 FINISH 决策处加入。它反映团队完成任务的结果，通过 GIA 的后续回报影响其安排；不直接广播成所有 HI 行动的奖励。

C_H、C_G、S_H 中的加权比例均使用评分前确定的适用条件或实际关键断言：条件满足计 1、不满足计 0，再按权重平均。判断材料不足以确定时记录无法确认，不擅自当作错误。合法但空泛的报告 C=0、S=0；因模型反复生成无效输出而耗尽格式重试时，该角色 episode 的终止奖励为 -1。基础设施中断单独记录，不冒充策略作答错误。无法评分而排除的比例与失败原因需要报告。

对证据受限案例，参考材料分别记录现实真值和在该环境中合理的回答要求。只有符合真实可回答性条件的谨慎结论才能获得相应 C_G，不使用删除证据前的标准答案强迫模型猜测。

### 6.3 过程进展与错误

定义 Φ_H(w,t) 为本 Workspace 在 t 时刻已经可靠完成的局部证据条件的加权比例。例如，实际读取可用日期、完成正确片段对应、准确复用已有原片。范围为 0–1。

定义 Φ_G(k) 为 GIA 在某次决策/轮次完成后，已由实际证据和报告支撑的全局必要条件覆盖，范围为 0–1。报告里的未核实 Finding 不自动算条件闭合。

进展按变化计算：

    p_H(w,t) = Φ_H(w,t+1) − Φ_H(w,t)
    p_G(k)   = Φ_G(k+1) − Φ_G(k)

重复读取同一事实不反复增加覆盖；正确撤回错误结论可以进入过程修复样本，但不因反复写错再纠正而反复产生新的事实奖励。

v_H、v_G 分别表示可定位到当前决策、且依据当时信息可识别的错误：如使用错误素材 ID、明显不适合的工具、已知反证下重复错误前提、将上传时间说成拍摄时间。一个动作多项同源错误合并，v 取 0 或 1。仅工具无命中、外部接口失败或客观事实超出可见范围，不自动令 v=1。

c 表示该决策消耗的预算比例，起始计算为 0.5 × 本步输出 token / 角色输出预算 + 0.5 × 本步工具成本单位 / 角色工具预算。HI 对自身行动和工具成本负责；GIA 的 INVESTIGATE 计入所安排轮次的工具成本。分母使用采样前给定的预算，不使用事后实际总消耗。以预先测得的固定工具成本单位计算，避免用偶发网络延迟惩罚策略；每个角色 episode 累计成本最多计 1。

逐步奖励为：

    r_H(w,t) = 0.3 × p_H(w,t) − 0.2 × v_H(w,t)
               − 0.05 × c_H(w,t)
               + [本步提交报告] × Q_H(w)

    r_G(k)   = 0.3 × p_G(k) − 0.2 × v_G(k)
               − 0.05 × c_G(k)
               + [本步 FINISH] × Q_G

进展总贡献最多约 0.3，终止结果最大为 1，成本总扣分最多 0.05。必要准备步骤的即时进展可以为零；SFT 教会它如何操作，后续回报仍可以传回这些步骤。使用更多种工具、更多 E 或更多 Workspace 不单独发奖。

### 6.4 共享证据的归属

兄弟 Workspace 刚提交一个新 E，不能直接提升当前 HI 的 Φ_H。当前 HI 实际读取、定位、比较或正确解释该 E 后，才满足它自己的使用条件。发现来源和复用来源可以分别有价值，但不同 E 中的同一事实只算一次。

GIA 的 Φ_G 对全局事实合并计数，三个报告重复同一来源不会得到三份进展。INVESTIGATE 的执行效果在该轮报告返回后评价；同一轮的全部安排作为这一 GIA 决策的结果。

固定 HI 参数降低了训练 GIA 时的变化来源，但不能消除工具随机性，也不提供严格因果归因。对有争议的关键计划，在同一初始全局状态、同一 HI 版本和相同预算下重跑两个计划，至少各两次；结论不稳定时不制作强修复标签。

## 7. 逐步奖励怎样更新参数

采用 REINFORCE++ 风格的无 Critic 策略优化。每一步有自己的奖励，先计算从该步往后的回报，再按角色分别归一化。它避免为两套策略额外训练两个价值网络。

普通 GRPO 可以合法比较从同一初始任务采样的完整系统轨迹；本设计不采用“把不同局部输入下的 HI 第 t 步组成一组”的错误用法。过程样本来自不同状态，按角色归一化更容易接入现有动态调查。

### 7.1 轨迹边界

- HI：一个 Workspace 从创建到报告，是一条训练 episode。同一角色参数共享，但不同 Workspace 不拼接成同一回报序列。
- GIA：一次原始调查中它的全部决策，是一条 episode。INVESTIGATE 后的环境转换包含该轮 HI 实际执行。
- HI 的回报在自己报告处结束；GIA 的回报到最终回答结束。

以 γ=1 为起点：

    G_H(w,t) = Σ[u≥t，到本 Workspace 结束] r_H(w,u)
    G_G(k)   = Σ[j≥k，到本次调查结束] r_G(j)

这与“全条轨迹每一步收到同一个终分”不同：发生在第 5 步的错误进入第 5 步及其前序的未来回报，不进入第 6 步之后的回报；后续证据收益可以回传到必要的准备步骤。

稠密回报仍不保证每个错误动作的最终净梯度都为负，也不等于精确因果分解。对可确定错误持续提供经执行验证的正确决策 SFT，并在开发数据上检查相应错误率。不能仅靠奖励公式声称归因已完全解决。

### 7.2 训练损失与数据连接

1. 在更新前采集完整 episode 的实际决策输入、输出 token、采样 log probability、角色与 episode ID。
2. 在 episode 上计算逐决策回报，再映射到该决策输出的 token。
3. 按当前被训练角色的有效决策计算均值和标准差；零方差或接近零方差时跳过无信息更新，避免数值放大。
4. 使用 PPO clipped policy loss，起始 clip=0.2。只计算当前角色输出 token；工具观察、教师评语、其他角色输出均不计算该策略损失。
5. 保留小系数 KL 约束，参考为该角色的初始 SFT 策略；可复用相同基础权重及固定参考 LoRA，不新增可训练角色。KL 作为独立损失项，先按动作内输出 token 平均，再按案例平均；不将数千个 token 的 KL 直接累加到最大约 1 分的终止奖励中。
6. 同一批采样数据只做一次训练遍历，之后重新采样。记录实际 token，不能重新编码出一套与采样概率不对应的 token。

因为 Harness 会重建或压缩上下文，不能假设后一轮输入一定以前一轮完整文本为前缀。回报先沿 episode 关联计算，再把各轮作为独立模型输入训练。不能逐轮拆开后让 RL 把每轮都误认为独立终止。

采用按案例、Workspace、动作归一的抽样与权重：先使案例贡献相近，再使案例内 Workspace 贡献相近，最后在动作输出内求平均，避免长报告和大量 Workspace 自动得到更大训练权重。

实现可基于 verl 的 token reward、response mask 和 REINFORCE++ 优势估计接口。实际需要适配 ForenSearcher 的多角色 episode 和状态重建，单独设置一个 reward 函数不足以完成接入。[verl 源码文档](https://verl.readthedocs.io/en/latest/_modules/verl/trainer/ppo/core_algos.html)、[扩展说明](https://verl.readthedocs.io/en/latest/extend_guide.html)

## 8. 完整训练流程

### 阶段 A：评分和执行试运行

用 100 个训练案例执行材料整理、rubric、教师轨迹和逐步评分。实测可用来源比例、教师成功率、轨迹长度、工具失败、评分耗时与峰值显存。

人工核对关键事实并检查评分器的错误接受率，特别覆盖正确结论配错误引用、正确引用配错误推断、失败调查中的合理动作和共享证据误归功。自动接受条目的精确率目标为 95%，同时报告抽样量和不确定性；这个数字不是已达到的结果。

评分偏差应先修正对应的标准或执行方式。无法用当前工具核查的视觉/音频条件不进入强自动奖励。

### 阶段 B：初始 SFT

扩展首批 1,000 个原始案例。每题通常 1 条教师轨迹，必要时第二条。合格决策拆成 D_HI 与 D_GIA，两个角色分别训练。

若 800 条完整调查可用，平均每条提供 35 个 HI 决策、5 个 GIA 决策，则约产生 28,000 与 4,000 个样本。这仅说明数量换算，实际样本以逐步审核结果为准。

所有步骤都接受检查，但只模仿有依据的目标输出；最终失败的调查可以贡献正确步骤，成功调查不自动使全部步骤合格。配额不足时补足有用案例，不复制大量同义改写凑数。

### 阶段 C：交替过程 RL

一次 HI 更新批次：

1. 固定当前 GIA 与 HI 参数，执行 16 个案例，每例采样两条完整调查，共 32 条。
2. 卸载学生推理进程，加载 235B；程序与教师对实际记录评分。当前参数尚未更新。
3. 卸载 235B，加载 HI 训练策略，计算各 Workspace 内逐步回报，仅更新 HI。
4. 下一批必须使用新的 HI 重新采样。

一次 GIA 更新批次：

1. 使用当前 HI，重新采样 32 条完整调查。
2. 分阶段评分 GIA 的实际决策、轮次进展与最终回答。
3. 只更新 GIA。下一批使用新 GIA。

同机切换产生时间开销，但延迟评分本身不破坏近策略采样；关键是采样至更新期间没有改变该策略。不能为了少加载教师，把一次采样数据反复当成多个“在线”训练轮次。

初始安排三个训练周期，每周期 8 个 HI 批次和 8 个 GIA 批次，共 48 批、1,536 次完整学生调查。每批只包含当前策略的真实采样，失败轨迹也参与可靠可评部分的学习。该规模是第一轮研究预算，不声称等价于 Harness-1 的完整训练计算量。

### 阶段 D：数据和 Harness 迭代

每个周期结束后，按真实错误归纳更新，而不按单次得分高低扩写提示。

- Rubric：从训练轨迹中新发现的真实错误和等价证据提出补充，核查后用于下一周期；同批轨迹采用同一版标准，必要的事实条件不会因本批全满足而删除。
- 数据：增加已验证的局部修复、替代路线和证据条件对照。每周期先控制在 100–200 个局部修复点，避免为每个动作展开整棵搜索树。
- 参数：每周期加入一小轮可靠决策 SFT，约 80% 复习原始合格数据、20% 使用新修复数据，随后重新采样 RL。
- Harness：最多尝试两个有明确错误依据的通用角色提示修改，在开发集检查目标错误率和任务效果；不改 E/F 含义、工具接口、访问边界或评分标准。

“模型学得更好”和“rubric 更会评价”分别验证。最终测试标准不跟随被训练模型的错误动态改变，也不根据测试失败生成训练补丁。

## 9. 起始参数和显卡安排

| 参数 | 初始 SFT | 过程 RL |
|---|---|---|
| 基础模型 | Qwen3-8B，两套独立 LoRA | 延续对应角色 LoRA |
| 精度 | BF16 | BF16 策略与采样优先保持一致 |
| LoRA | r=32、alpha=64、dropout=0.05 | 同左 |
| 训练层 | 注意力 q/k/v/o 与 MLP gate/up/down | 同左 |
| 学习率 | 1e-5 | 2e-6 |
| 训练遍历 | 起始 2 epochs，按开发结果选择 | 每次采样批次 1 次遍历 |
| 有效优化批量 | 64 个决策，micro-batch=1，梯度累积 | 32 条调查拆出的目标角色决策，按 token 分批累计 |
| 上下文 | 首轮 16K；足够后再测 32K | 使用相同状态预算 |
| 算法 | 交叉熵，仅输出 token | REINFORCE++ 风格、γ=1、clip=0.2、KL 系数起始 0.01 |
| 节省显存 | 梯度检查点、序列长度分桶 | 同左；不加载 Critic |

16K 是训练试运行的上下文预算，教师生成、SFT 重放和学生运行都遵守同一规则。不能只在训练时从左侧截掉超长上下文。32K 是否合适取决于真实序列分布与显存测量。

试运行可从每 Workspace 最多 32 次模型决策、每次调查最多 4 个调查轮次及总工具预算开始，均属于训练环境预算；Workspace 数量和具体调查路线仍由 GIA 在预算内决定。最终预算应依据真实任务完成率和轨迹长度设定，不能靠紧上限制造大量不可完成任务。

### 显卡分时使用

- **235B 阶段**：使用现有 8 卡服务，小并发生成、评分。控制其 KV cache，为实际媒体工具保留可用显存；是否能同时驻留必须测量，不能将 640 GB 全部当作自由空间。
- **学生采样阶段**：卸载 235B。可先使用 4 张卡运行两套学生策略推理，2 张卡运行媒体工具，其余用于增加并发或缓冲；部署拓扑按现有服务适配。
- **优化阶段**：停用不需要的推理/媒体进程，8 张卡训练一个角色；另一个角色只保留 checkpoint。用 FSDP/ZeRO 等已有分布式训练支持处理参数与优化器状态。

235B 不进行全参数训练。对它的视觉判断不作假设；如果实际调用的是文本 Qwen，它依靠工具观察和人工核对后的参考材料完成语义审核。

将总时间拆成教师示范、学生采样、评分、模型加载、梯度更新和评测六部分记录。用首批实测均值乘以计划批数估算 GPU 小时，不把题目数量直接换算成固定训练天数。不开付费模型 API；开放网页检索仍需要网络和可用的检索提供方。

## 10. 实验验证与研究贡献

主张一：证据支撑、按角色和决策边界编制的 rubric，比只有任务终分或泛化检查清单更能减少长调查中的证据误用。

主张二：用实际成功/失败路径和证据条件对照更新训练数据，能够提高分工适应、错误恢复与新来源泛化。

最小比较组：

| 组别 | 用途 |
|---|---|
| 逐决策 SFT | 检查 RL 是否带来额外收益 |
| SFT + 仅 episode 结果奖励，采用相同优化器 | 隔离过程反馈的作用 |
| SFT + 固定、证据支撑的过程 rubric | 检查可靠过程监督本身 |
| 完整数据构造与迭代训练 | 检查对照提炼、条件变化与更新的增益 |

额外只做一个针对协作的验证：对训练前后的 GIA、HI 进行四种搭配评测，比较各角色独立改善和组合适应。资源允许时在开发子集移除证据条件对照数据，用同样采样量检查它的贡献。

比较组使用相同基础模型、可用训练案例、主要工具预算和采样计算量；额外教师调用、人工时间和工具成本独立报告。主结果除自动指标外，还抽查引用支持和关键事实错误。相同案例重复运行用于估计波动，不能把重复运行当新增测试案例。

Rubric、逐步奖励、交替训练和对照数据都已有先例，不能分别宣称首次提出。可争取的贡献在于：面向共享证据的视频调查，将任务事实、角色责任、具体行动与可核验材料连接起来，并证明这种数据和训练设计提高了跨来源核查、错误恢复与协作效果。实际新颖性仍需围绕最终实现进一步查新。

## 11. 工程交付范围

训练接入需要完成五项配套工作：

1. 将选定数据转换成输入材料与训练侧参考材料，并完成事件/源视频分组。
2. 生成、执行和校准 rubric，保存具体判断依据。
3. 导出决策级 SFT 数据，以及带角色、Workspace 边界、采样 token 和 log probability 的 RL 数据。
4. 接入按角色回报计算与单角色更新，支持分时采样、评分和优化。
5. 使用独立开发和测试数据评价事实、证据、过程错误与计算成本。

交付数据应能回答：该动作由谁作出、当时看到了什么、真实执行得到了什么、哪个条件满足或失败、评分依据在哪里。缺少这些信息的漂亮长轨迹，不能视为高质量过程训练数据。
