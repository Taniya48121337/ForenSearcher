# datagen 第五块砖：三层核验器 verify/（2026-09-15）

位置：`src/foren_searcher/datagen/verify/`（context、exec_checks、anchored、sufficiency、verdict、judges、reverify）。测试 `tests/test_datagen_verify.py`（15 项，含对试点 run `averimatec_441_q0_r1` 真实证据库的冒烟）。

## 和以前的评审有什么不同

以前：评审员拿着演员当时看到的桌面（分页截过的正文片段 + 附图）按七个维度打 0–4 分，评审员和教师是同一个 Codex 账号，最后只留 3–4 分的行。它核的是"演员看到的片段能不能撑住结论"，不是"证据原文能不能撑住结论"，也说不出错在哪一类。

现在：三层、逐条 Finding 核对、每条错误从 `errors.py` 的 22 种里挑名字、核验模型必须与教师分离。

## 三层各做什么（大白话）

第一层 `exec_checks`，纯程序，不花钱。查：引用的 E 在证据库里存不存在、提交报告那一刻看不看得见（从 trajectory 的最后一次 model_input 取可见集合）、COMPLETED 报告是不是空的、Finding 有没有引用、结论里的数字（≥10 或带小数）能不能在所引 E 的原文里找到；有案卷（`cases.py`）时再查：来源是否踩了排除名单、状态和案卷标注是否一致、应有的实体/标签/数值/日期/时间区间有没有出现、必需证据有没有被引用。判得死的记 `hard`（引用不存在、踩排除名单、必需证据没引用却报 COMPLETED），拿不准的记 `flag`（数字不在文本里——可能来自图片或计算），交给第二层。

第二层 `anchored`，模型逐句对原文。对每条 Finding 的每条所引 E，核验模型只看"这句话"和"这条 E 的全文或图片"（从 Store 取全文，最长 2 万字符），不看任务、不看演员桌面，回答三态：supported / contradicted / not_found，并且**必须给一段原文引语**。引语由程序回查是否真的在原文里（去空白后子串匹配，≥6 字符）；对不上就当 not_found，不采信。三态映射到错误类型：有 E 反驳 → `wrong_citation`（critical；模型提示细字读错/口径不一致时改记 `misread_fine_text` / `sloppy_numeric`）；没有任何 E 支持 → `unsupported_assertion`；有支持但混入不相关的 E → `wrong_citation`（minor）；来源只是转述而句子写成事实 → `attribution_drift`；模型提示以偏概全 → `scope_overreach`。图片 E 需要像素，核验模型看不了图时记为 pending，不瞎判。

第三层 `sufficiency`，模型看整份报告。输入任务全文 + 案卷必需证据清单 + 报告，回答每项要求 covered 没有、仅凭报告能否回答、状态应为什么。映射：未覆盖 → `omitted_required_fact`；报 COMPLETED 但有 must_cite 项未覆盖 → `completed_without_finishing`；报 INCOMPLETE 但已能回答 → `incomplete_though_answerable`。与第一层重复的按类型/键去重。

## 处置与污染

`Verdict`：错误列表、`disposition`（任一 critical 定错或 ≥2 个 major → negative；有 pending 或只剩 flag → uncertain；否则 positive）、`tainted_findings`（含传播型错误的 Finding，按 `errors.py` 的 propagates 规则）、跑了哪几层、每条判定的引语、核验器版本、核验模型名、规格 hash、渲染档位。一行一个写 `verdicts.jsonl`，可读回。

## 重核试点（第 0 轮错误分布）

`python -m foren_searcher.datagen.verify.reverify --runs experiments/sft_data/runs --out experiments/sft_data/verdicts_r0.jsonl` 遍历每个 run 的 `store.sqlite3`，对每份已发布的 Workspace Report 跑核验，输出 verdicts 和一份 summary（处置分布、各错误类型计数、含定错的报告数、被污染的 Finding 数、pending 原因）。默认 `--judge none` 只跑第一层；`--judge openrouter --model <与教师不同的模型>` 跑三层，密钥仍从 `.local/openrouter.json` 读，记账角色 VERIFIER。`scripts\重核第0轮.cmd` 是第一层版本的一键运行。

在云端对 `averimatec_441_q0_r1` 冒烟：1 份报告，第一层零硬错、零 flag（结论里的 2023 年在 E3/E6 原文中），处置 uncertain（待模型层）。

## 已知缺口

- 图片证据的第二层需要能看图的核验模型；OpenRouterJudge 已按 visual_qa 的格式附图，但未在真实模型上试过。
- 重核时还没有案卷（cases/）可用，所以来源排除、必需证据等案卷断言在第 0 轮不生效；案卷化落地后加 `--cases`。
- 核验器本身的准确率要用扰动器（perturb.py）注入的已知错误来校准（calibrate），尚未写。
