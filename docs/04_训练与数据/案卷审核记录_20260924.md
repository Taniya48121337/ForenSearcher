# 案卷审核记录：11 份起草案卷 → cases/（2026-09-24）

审核人：总控会话（本轮由我审，不再等人工）。对象：`experiments/sft_data/cases_draft/` 的 11 份程序起草案卷。做法：逐案读 run 的总任务、GIA 首轮任务、最终答案、各工作区报告（校准后的处置与污染 Finding）和所有被引 E 的来源/获取方式，然后重写 requirements、required_evidence、组规则与 checks，`Case.load` 校验并核对每个 url_pattern / acquired_by 都能在 run 里匹配到 E。结果全部挪进 `experiments/sft_data/cases/`（true_4124903 保留手写版），11 个 case 无划分泄漏。

## 审核原则（和起草工具的差别）

1. **要求写的是"正确的调查必须建立什么"，不是"这个 run 做了什么"**。起草工具把首轮任务分句拼起来，我改成 2–4 条各自独立的判断，最后一条通常是"限制/不能确认的内容"，must_cite=False。
2. **证据分组用 `required_evidence_rule`**：同一事实的两个来源写成 any_one_of（Snopes 或 Breathalyser；The Blaze 或 Free Beacon；MNopedia 或 MNHS 教育页），不再要求每个来源都引。辅助来源（FMCSA 指南、LA Times、MinnPost、YouTube 字幕）must_cite=False。
3. **媒体对照类（videosham）统一四条要求**：画面/时序差异及两侧时间位置；音轨可得性与声音差异；差异对含义的影响；未能确定的内容（不预设候选 B 的来源身份）。证据全是派生：frames 必引，media_profile 只在音轨数是结论一部分时必引（0069），alignment / crop 都是线索不必引。
4. **checks 保守**：全部案卷都没有 label_expected（仓库里没有数据集标注，等标注文件到位后补）；不写 date_in_range（历史事件的年份无意义）；实体检查只保留 true_4124903 的"耶拿桥"，并标 `requirement: REQ1`、`aliases: ["pont d'Iéna","Iéna"]`（所引证据是法文）。
5. **split 全部 dev_train**。11 个案例还谈不上五份划分，等到 30+ 时按 family 一次性分配，不要现在零散地分。

## 审核中发现并已修的核验器问题

案卷的 `entity_in_evidence` / `numeric_in_evidence` 和 label_expected 一样是对每个工作区报告跑的——只看视频的工作区当然不会写"Pawlenty"。已让子代理把 `Check` 加上 `requirement` 作用域（exec_checks 按工作区对准的 REQ 跳过），答案单元统一查全部 checks（实体不在答案 → omitted_required_fact；在答案但不在所引 E 文本 → unsupported_assertion flag），并加 `aliases` 处理跨语言实体。全套 129 通过 / 2 跳过。

## 起草工具的评价

程序起草在证据清单上是可靠的（url_pattern / acquired_by 11/11 全部匹配到 run 里的 E，一条没漏），在要求文字上不可靠（分句拼接、模板化），在 checks 上过于保守到几乎没用。结论：它的定位是"证据清单 + 审核单"，要求文字必须人（或总控）改写；等本地核验模型到位后，可以让模型按上面的审核原则出第一稿。
