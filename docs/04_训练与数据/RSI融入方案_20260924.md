## 0. 一页结论 **[09-28 已精简，见顶部修订表]**

**两种 RSI 在我们框架里各有天然的位置，不需要硬加。**

- **免训练 RSI（内环）**：权重冻结，改 harness。可改的东西我们已经全部版本化了：`specs/hi@x.y.z`、`gia@x.y.z` 里的 student_prompt / teacher_instruction / harness_params，再加两样新的可演化对象——GIA↔HI 之间的**接口契约**（任务写法、报告字段）和一份按错误类型登记条目的**调查手册**（ACE / ReasoningBank 式经验记忆）。不改代码。
- **需训练 RSI（外环）**：HI、GIA 两套 LoRA **交替**训练，而且**互相给对方造数据**：GIA 派出的任务就是 HI 的训练分布，HI 交回的真实报告（包括烂报告）就是 GIA 的训练分布。随着轮次推进，训练数据里学生自己生成、经核验通过的比例上升，教师只做修补。
- **核验器（地基，也会演化但最慢）**：你们已有的三层核验 + 召回率/精确率校准就是第三根杠杆。评测用的参考核验器冻结，训练用的核验器可以升版。

**把三根杠杆串起来的是一个路由器**：错误账本（`verdicts_*.jsonl`，已有）按 `错误类型 × 角色` 统计后，按一棵很简单的决策树决定每类错误该交给哪根杠杆、哪个角色：

1. 这类错误核验器抓得准吗？不准 → 先修核验器。
2. 错误是角色自己的，还是上游角色喂进来的（`tainted_input`、`premise_smuggling`）？是上游的 → 交给上游角色。
3. 教师在同一规格下也犯吗？也犯 → 是规格/harness 诱发的，走**免训练内环**；教师不犯、学生犯 → 是能力差距，走**需训练外环**。**[修订]** 这里的理由不是"训练会把错误抄进学生"：教师出错的行会被核验器筛掉，本来就进不了训练。真正的损害是这些难状态上没有正例、数据产出低，内环改的是"教师在这些状态上能不能产出正例"。

**[修订]** 这条"教师–学生差距"判据只作为**先验**，不当作已经成立的规则。每轮对前 3 格错误做小预算的双干预（一个内环候选 + 一次针对性 LoRA 增量），实测哪根杠杆更有效，作为反事实真值。论文报告"先验判据预测反事实最优杠杆的准确率"。和 SIA 让 Feedback-Agent 凭经验选相比，我们的判据是可测、可被证伪的。

**你们已经手工迭代过很多轮**：rubric r1→r6、教师指令 r3→r8（内环的人工版）；`calibrate@0.3.0` 的 R1/R2/R4 校准规则，以及召回实验暴露的 drop_required_finding 0/4（核验器杠杆）；第 0 轮 SFT 链路（外环，待真实训练）。**[修订]** `hi@0.2.0` 只是把运行时已有的时间预算附注收进规格，是对齐而不是修复，不能当内环有效的例子。RSI 要做的是把这些手工动作变成同一个脚本、同一套判据、同一种门控。

**贡献措辞建议**（第 3 节展开）："harness + 权重联合演化"这个概念已被 Co-Harness、HASE、SIA 占了，不能说首次。可以说的是：（1）第一个在**双角色**调查系统上、以**证据核验**而非模型自评驱动、并按**角色和杠杆路由**的 RSI 循环——Co-Harness 原文把多智能体版本列为未来工作；（2）两个角色在外环里互为对方的数据生成器和课程；（3）一组针对 Seed 三篇负面结论的正面证据：核验分与留出提升的相关性、改动方向一致率、植入缺陷定位准确率。

## 1. 先把"两种 RSI"说清楚

2026 年 7 月的 RSI 综述（2607.07663，1250 篇）按"改进的是什么"分四类：部署期自我演化（权重冻结，改输出、代码、harness、技能库）、训练期自我迭代（模型产出数据或奖励再更新自己的权重）、自我评估（评估器本身作为改进对象）、自动科研。你说的两种就是前两类；第三类是前两类能不能成立的前提，综述称它为"承重支柱"，我们必须显式做。

综述还有两条区分，直接决定我们怎么定位：

- **有界 RSI vs 开放 RSI**：有界 RSI 针对固定外部标准收敛、可评估；开放 RSI 连标准和机器一起改，验证问题悬而未决。我们应明确定位为**有界 RSI**——外部标准是数据集真值 + 案卷要求 + 冻结的参考核验器。
- **闭环程度**：人在环中 → 人在环上 → 全闭环。Seed 的 Self-Developing Agents 专页把依赖"黄金核验器"的循环叫"半环 RSI"。我们的核验器不是黄金的，是自己搭、自己校准、自己也会升版的；这让我们比半环多走一步，但也意味着必须报告核验器自己的精确率和召回率。第一轮人在环中，之后人在环上（只看门控报告和抽检）。

### 2.4 反面证据：必须正面回答的三篇（字节 Seed，2026-09-01）

- **Aspire**（2608.31111）：模型自己决定训练什么时，12 个最终 checkpoint 均值只有 1 个超过底座，24 次运行只有 3 次提升；典型失败是"表面进步其实是从训练引起的退化里爬回来"、答案格式塌缩、在自己设计的验证清单上涨但隐藏评测不涨。
  → 我们的外环**不让模型自主选训练配方**；训练配方固定，模型能影响的只有"哪些数据经核验入选"。每轮必须和上一轮 checkpoint、也和底座比。
- **S³Gym**（2608.31100）：自测、自评、自改三步中，认出好动作不等于学会；参数训练在部分任务上大涨、在另一些上严重负迁移。（按 09-15 设计记录，自评与提升的相关约 −0.01。）
  → 我们必须报告**核验分变化与留出集提升的相关系数**，这是"经验整合"成立的直接证据。
- **HarnessDev**（2609.01437）：演化阶段 64 次修改只有 34 次（53.1%）在留出集上方向一致；18 个代码组件从未触发；换执行模型后改动效果大变。
  → 我们报告**方向一致率**、**触发率**、**跨执行模型迁移**三个数，并且内环的改动永远用"当前真实执行者"（训练后的学生）评估。

## 3. 新颖性：哪些不能说、能说什么

**不能说**：首次把 harness 演化与权重训练结合（Co-Harness、HASE、SIA 都做了）；首次多智能体共同演化（Agent0、SAGE、MAE 都做了）；首次用错误类型驱动 harness 修改（Co-Harness 的归因表、Self-Harness 的弱点挖掘）。

**能说的三点**，每一点都要有对应实验撑着：

1. **以外部参考材料为锚的核验、按角色与杠杆路由的双角色 RSI**。别人要么单智能体（Co-Harness、HASE、ModularRSI、RRSI），要么多智能体但只改提示、LLM 两两评判（RHI），要么多智能体但只训练权重、没有 harness 演化（Agent0、SAGE）。我们在同一循环里有两个角色 × 三根杠杆，路由靠两个可测量：角色归因（v2 §2.5）和教师–学生差距。**[修订]** 证据是可测的新量：路由先验对反事实最优杠杆的预测准确率（双干预），以及跨角色错误传播的归因准确率。E4 植入缺陷改为由项目外的人盲设计。"真值核验"的说法不再使用：只有标签是真值，过程判定是以参考材料为锚的 LLM 核验，要报告它在人工金标上的精确率和召回率。
2. **两个角色在外环里互相造数据、互相当课程**，并用交叉搭配实验量化这种互助（协同项）。对应实验 E3。
3. **对 Seed 三篇负面结论的正面测量**：核验分与留出提升的相关性、方向一致率、触发率、跨执行模型迁移、内化比例。对应实验 E2、E5、E6。

措辞沿用 DESIGN §7：写"据我们所知，这是第一个在 N 个异构视频核查任务上……的工作"，把"第一"限定在可核实的范围内。Co-Harness 的多智能体版本随时可能出，所以论文的差异点要落在 1 和 3 上（真值核验与路由判据），不要落在"多智能体"这个标签上。

                  │ 接受的 harness 用来产数据                          │ 能力差距

### 4.1 错误账本（已有，只加字段）

就是现在 `verify/` 产出的 `verdicts_reports.jsonl` + `verdicts_units.jsonl`，单元是 report / step / plan / answer。为了路由，每条错误多记三个字段：

- `actor_kind`：teacher | student@rN | base —— 同一规格下谁产出的决策；
- `origin_role`：按 v2 §2.5 归因后的责任角色（HI 的 Finding 被 GIA 引用出错，origin_role=HI）；
- `spec_hash` + `verifier_version`（已有）。

diagnose 的输出就是一张表：行 = `role × unit × error_type`，列 = 教师率、学生率、底座率、核验器在该类型上的召回/精确率、上游归因占比。

### 4.2 路由器：三问决策树 **[09-28 已精简，见顶部修订表]**

对 diagnose 表里频次排前 k（建议 k=3）的每一格，按顺序问：

| 步 | 判据 | 成立时 | 依据 |
|---|---|---|---|
| ① 核验可信 | 该错误类型的注入召回 ≥ 0.8，且人工抽检精确率 ≥ 0.85 | 否 → **核验器杠杆**：升 verifier，本轮不对这类错误做其他动作 | 你们 09-23 的召回实验：drop_required_finding 0/4 就属于这一格，应先修 sufficiency 层而不是改 HI |
| ② 归因 | `origin_role ≠ 出错角色` 的比例 ≥ 50% | 是 → 改道到上游角色，再从第 ③ 步判 | v2 §2.5；Who is the Agent to Blame |
| ③ 教师–学生差距 | 设教师率 t、学生率 s（同规格、同案例池）。t ≥ 0.5·s 或 t 本身 ≥ 阈值 | 是 → **免训练内环**（规格诱发，训练只会把错误抄进学生） | Co-Harness 把 agent_error 排除出 harness 修复的反向版本 |
| | s − t ≥ δ（显著） | 是 → **需训练外环**：为该角色、该错误类型造对照/修补/恢复数据，提高采样配额 | — |
| | 两者都不成立 | 记入观察，不动 | 防止为噪声改规格 |

**[修订]** 补充规则：
- 教师率 t 用"教师只拿 student_prompt、不拿 teacher_instruction"的探针测，保证与学生输入相同；
- 两个条件同时成立时先看 s−t；
- 没有人工精确率和注入召回数据的错误类型，一律记为"观察"，不进路由。目前除 report 单元的 4 类内容错误外，全部属于这种情况。

路由器本身要能被验证，否则它只是一个好听的规则。**[修订]** 主要验证手段是双干预实验给出的反事实真值；植入缺陷测试（E4）作为补充，缺陷由项目外的人盲设计。

### 4.3 内环：免训练 RSI **[09-28 已精简，见顶部修订表]**

**可演化对象（白名单，不改代码）**

| 对象 | 例子 | 版本规则（沿用 datagen 规格说明） | 影响 |
|---|---|---|---|
| teacher_instruction | 教师"不因再确认一下反复切换"类要求 | patch | 只影响数据，不进学生输入 |
| harness_params | image_input_limit、read_page_chars；Harness-1 机制移植完成后再加 focus 容量等 | **[修订]** 改变学生输入分布的升 minor | 教师和学生运行时都变。**前提：运行时要先改成从规格读参数，目前只记录不生效** |
| 调查手册（新增） | 按错误类型登记的短条目，如"上传日期不能写成拍摄日期"，每条带 `targets`、来源轨迹 | minor | 进 student_prompt 的一个独立块，有容量上限；**含实体、数字、URL、日期的条目由程序拦截**，并与 test 做 n-gram 审计 |
| student_prompt 其余部分 | 角色说明、输出格式、**GIA"如何写任务"的文字指导** | minor | 同上 |

**[修订] 明确不演化的东西：**
- **接口契约**：给 GIA 任务或 HI 报告加字段，会重新引入 DESIGN §6 第 13、18、19 条否定过的设计，而且要改解析代码。写任务的质量只通过 student_prompt 里的文字指导来改，task 仍是一个字段。
- **state_renderer**：v2 §10 规定整个实验期不变，全项目统一一个档位。
- **工具接口、E/F 的含义、访问边界**：沿用 09-11 方案 §8D 的规定。
- **Harness-1 机制**：移植完成前，其参数不进白名单；移植时 focus 的重要性由 HI 判定（DESIGN §6 第 10 条），去重不得合并不同来源的转载。

**谁来提改动**：主实验用强模型（教师 Qwen3.5-122B，或当前 API 教师）做提议者，输入按 Meta-Harness 的组织方式给：当前规格与历史版本、diagnose 表、该错误类型下同一案例的成功/失败轨迹对（ModularRSI 的对照分析）、以往被拒改动及原因。每次只针对路由器分来的一格错误、只动一个对象（ModularRSI 的逐模块原则），每轮最多 K=4 个候选。消融：第 3 轮起用训练后的学生 GIA 当提议者（自指版本），看提议质量是否随学生变强而变好——这是"递归"最直接的检验，做成了是加分项，做不成不影响主线。

**怎么验**：

1. 回归验证（Self-Harness）：在 dev_select 上已通过的案例不能掉。
2. **门 A**：权重冻结，候选规格 vs 当前规格，在 dev_select 上用**当前学生**作执行者各跑 2 个种子；目标错误率下降、非目标错误率不升、原生指标不降才接受。执行者必须是学生而不是教师——HarnessDev 发现换执行模型后改动效果大变。**[修订]** 补充几条规则：
   - 教师侧改动（teacher_instruction）另设"教师门"，执行者是教师，看数据产出与错误率。
   - student_prompt 和手册类改动只能"暂定接受"，下一轮重训后由门 B 定夺。原因是旧学生没见过新提示，直接评会系统性吃亏。
   - 每轮从 K 个候选里选出最优的**1 个**，再在 dev_confirm 上确认；确认结果参与决策，α 预先登记，按 Holm 校正。
   - 开跑前先做 A/A 测试（同一规格对自己），量出门的假接受率。
3. 修剪（RRSI）：删掉某条手册条目或某项参数改动后，门 A 指标不变，就删。**[修订]** 改用删除消融判断：一段提示文字有没有被"触发"没法直接测。

### 4.4 外环：需训练 RSI，两个模型互相帮 **[09-28 已精简，见顶部修订表]**

训练算子本身沿用已定的方案：两套 LoRA，按角色分开 SFT；后期可接交替 REINFORCE++（09-11 方案 §7）。RSI 加在"数据从哪来、谁给谁造数据"上。四条互助通道：

**通道 1：GIA → HI，任务分布对齐（on-policy 伙伴数据）。** 就是 v2 §4 的来源 E。第 n 轮训练 HI 时，HI 的任务来自第 n 轮的学生 GIA，而不是教师 GIA。否则 HI 学的是教师的任务分布，部署时却面对学生 GIA 的任务。

**通道 2：GIA → HI，课程。** 在训练模式下，给 GIA 额外的输入"HI 当前在哪些错误类型上薄弱"（来自 diagnose），让它围绕案卷要求出针对性的子任务。**[修订]** 这种调用是训练侧专用的包装：
- 它的输出打上 `origin=curriculum`，只作为 HI 的训练输入，**永不进 GIA 的训练行**（部署时 GIA 的全局视图仍是固定五块，DESIGN §2.3）；
- 课程任务在 HI 数据里的占比封顶 30%，让 HI 的任务分布不偏离部署分布太远。约束两条：任务必须通过 plan 单元核验（缺口驱动、无前提走私），不能为了"难"而偏离案卷；按 HI 的当前成功率筛，优先保留成功率居中的任务（Agent0 的思路，但这里是合作，不是对抗——GIA 的目标不是难倒 HI，而是让 HI 在还不会的地方多练）。

**通道 3：HI → GIA，真实报告与恢复样本。** GIA 的离线状态（来源 D）用第 n 轮学生 HI 的真实报告搭，而不是只用教师报告。学生 HI 的烂报告正好是 GIA 学"不轻信、改派复核"的材料：v2 里 `recovered_from_tainted=true` 的行权重 2，这类行现在几乎全来自教师，外环让它来自真实学生伙伴。

**通道 4：结果反馈给对方的奖励（进入 RL 阶段后）。** GIA 的逐轮奖励里已经有 round_yield（本轮派出的任务带回了多少被核实的新要求覆盖），它衡量的是"派给**当前这个 HI** 能不能办成"，天然把 HI 的能力边界传给 GIA。HI 的局部奖励 Q_H 不受 GIA 最终答案影响（09-11 方案 §6.1 已定）。要防 GIA 学会只派简单任务：round_yield 只算必需要求的覆盖，premature_finish 与 omitted_required_fact 扣分不变。

**交替顺序**：每轮先固定 GIA@n 训 HI（数据来自通道 1、2），得 HI@n+1；再固定 HI@n+1 训 GIA（数据来自通道 3），得 GIA@n+1。一次只更新一个角色，搭档不动，这是已定原则。**[修订]** 相应地，门 B 拆成 B-HI、B-GIA 两道，每个角色更新后各过一次，过不了只回滚那个角色。通道 3 固定混入一定比例的教师报告和旧版 HI 报告，防止"烂报告"随 HI 变好而消失。复习用的 r0 数据用当前规格从 run 日志重新导出，不与 v2 §10 的 spec_hash 规则冲突。

**[修订] 防钻空子。** 学生自采的数据经 LLM 核验筛选，会被推向"讨核验器喜欢"的写法：Finding 越少越含糊越好、堆引用、多报 INCOMPLETE、GIA 派简单任务。每轮报告以下三项，并各设上限或下限：
- 每项必需要求被 supported Finding 覆盖的比例；
- 可回答案例上的 INCOMPLETE 率；
- 每条校准规则在"不该被豁免"的反例注入上的假接受率。

**"自我"的比例：教师逐轮退出。** 第 0 轮全是教师数据。从第 1 轮起，每个案例先让学生系统跑 N 条（建议 N=4），核验通过的决策直接入选（STaR / ReST 式拒绝采样）；没通过的，从第一个出错的步开始让教师桥接一步、学生续跑，续跑通过才入库（FutureBridge 式，v2 来源 B 第二期）。每轮报告**教师依赖率** = 入选行里 assistant 输出由教师产生的比例。RSI 的一个硬指标是：这条曲线下降时，留出集性能不降。

**内化：内环的成果搬进权重。** 手册条目和契约字段在内环里证明有效后，下一轮外环用"带手册的学生 + 核验"产数据，训练后在**不带该条目**的最小规格下评测（Harness-Zero 的做法；它在同一个 Qwen3.5-9B 上的结果是蒸馏后反超挂着 harness 的版本）。内化成功的条目退役，手册保持短；这也缓解审计报告里 system prompt 已占 2.5–3.9K token 的问题。

### 4.5 地基：核验器也在演化，但评测标准不动 **[09-28 已精简，见顶部修订表]**

- 训练用核验器 `verifier@v` 可以升版，升版的理由只能来自两处：召回率校准的漏报（perturb 注入）和人工抽检的误报。学生在外环里暴露的新错误类型，要先做成新的注入方式、测出召回，再决定是否进入路由——这是"学生的错误教核验器"。
- 评测用参考核验器 `verifier_ref` 在实验开始时冻结，只用于门控和最终报告；再配原生指标和人工抽检。**[修订]** 训练用核验器和 verifier_ref 都改成本地固定权重：托管 API 的模型可能被悄悄换掉，没法真正冻结。verifier_ref 选与教师、训练用核验器都不同家族的模型，exploitation rate 只以人工判定为准。校准规则（R1/R2/R4 这类）一律先登记，再在推导出它的那个 run 以外测假接受率；人工金标集 ≥300 对 (Finding, E)，另加 ≥100 个 step/plan/answer 单元。否则会出现"核验器越改越松、循环越转越好看"。exploitation rate = 训练用核验器判通过、参考核验器或人工判不通过的比例，每轮报告。
- 核验器升版与规格升版不在同一道门里发生（v2 §10 原则保留）；升版后用新核验器重打上一轮的账本，保证错误曲线前后可比。

### 4.6 一轮怎么转 **[09-28 已精简，见顶部修订表]**（"双门"替代"每轮只改一样"）

v2 §10 规定"轮与轮之间只允许改一个东西"。两个环同时存在后，这条改为**每道门只改一个东西**，靠两道门保证可归因：

```
第 n 轮（身份：hi@a.b.c, gia@x.y.z, verifier@v, LoRA_HI@n, LoRA_GIA@n）
 1. 跑：学生系统在 dev_train 上跑（每案例 N 条）；教师在同一批案例上跑 1 条（用于算教师率）
 2. 核验：三层核验 + 单元核验 → verdicts_r<n>
 3. 诊断：diagnose_r<n>.json（role × unit × error_type，含教师率/学生率/召回/归因）
 4. 路由：route_r<n>.json（每格错误 → 核验器 / 内环 / 外环 / 观察）
 5. 核验器杠杆（若有）：升 verifier，重打账本，回到 3；本轮不再做其他改动
 6. 内环：≤K 个候选 → 回归验证 → 门 A 选出最优 1 个 → dev_confirm 确认 → 成为 spec@n+1（[修订] 不合并多个）
 7. 外环：用 spec@n+1 产数据（通道 1–3 + 自采 + 教师桥接）→ 训 HI → 门 B-HI → 训 GIA → 门 B-GIA
 8. 门 B 不过则回滚对应角色的权重，数据标 gate_failed 保留；门 A 不过则回滚规格
 9. 评测集：spec@n+1 + LoRA@n+1 在 dev_eval（从不参与决策）上跑一次，所有曲线只画在 dev_eval 与 test 上（[修订] 避免回滚造成的"天然单调"）；检索一律用录制回放
 10. 写 revision_log：每个改动的 targets、门 A/B 结果、确认集结果、触发计数
```

门 A 测的是"固定权重下 harness 改动的作用"，门 B 测的是"固定 harness 下权重更新的作用"，两者都可以单独归因。

### 阶段 0.5：教师侧内环，现在就能做（与阶段 0 并行；09-24 补）

内环分两半，执行者不同：

- **教师侧**：改 teacher_instruction 和 harness_params，执行者是教师，衡量的是造出来的数据好不好（核验通过率、各类错误率、每案例入选行数）。它**不需要训练过的学生**，现在就能跑。这就是 Co-Harness 说的"更好的 harness → 更好的轨迹"。
- **学生侧**：改 student_prompt、契约、手册，执行者必须是训练后的学生（门 A），所以要等第一次 SFT。

**[修订]** 现在账本里的错误全部来自教师（第 0 轮 unsupported_assertion 63、wrong_citation 24、completed_without_finishing 5），但这组数是 verifier@0.1.0 校准前的，其中有误报；教师也还是 gpt-6-astra，不是正式教师。所以它们现在只能记为"观察"，不能直接判成"规格诱发"。能先做的是教师侧内环本身：它的执行者是教师，不需要训练过的学生；外环在学生出现之前没有作用对象。等换成正式教师、核验器校准过后，路由才有意义。

阶段 0 里本来就要做的 gia@0.2.0（主提示对齐）和 verifier@0.3.0（充分性按工作区收窄），按循环的格式做一遍：先出 diagnose 表 → 写明针对哪类错误 → 改一样东西 → 在 dev 案例上用教师重跑比较 → 记 revision_log。这就是 DESIGN §8 说的"第一轮人工触发、人工看结果"，同时为阶段 1 的自动化攒下第一批真实改动记录。

### 阶段 1：循环骨架（约 1 周，基本不花 GPU）

| 模块 | 内容 |
|---|---|
| `datagen/diagnose.py` | 读 verdicts → diagnose 表；跨轮 trend |
| `datagen/route.py` | 4.2 的三问决策树，阈值进配置 |
| `datagen/revise/`（提议者接口） | 输入组装（规格历史 + diagnose + 成败轨迹对 + 被拒改动）；输出结构化 diff（对象、字段、旧值、新值、targets） |
| `datagen/gate.py` | 门 A / 门 B / 确认集；方向一致率、触发计数、exploitation rate |
| `specs/` 扩展 | `contract` 与 `playbook` 两个块，带容量上限与条目级 targets |
| `revision_log.jsonl`、`budget.jsonl` | 每个改动一行；每轮 GPU 时、教师 token、核验调用、人工分钟 |

这一阶段就可以跑一个**便宜版植入缺陷测试**：拿现有的教师 run，人为在 gia 规格里加一句会诱发前提走私的指令、或关掉 sufficiency 层的一个检查，看 diagnose + route 能否把它们分到正确的角色和杠杆。能分对，再进阶段 2。

### 阶段 2：学生侧内环单独试跑（1–2 周）

冻结 r0 学生，只跑内环 2–3 轮（教师侧内环从阶段 0.5 起一直在跑）。这一阶段不训练，成本主要是学生推理和核验。产出实验 E2 的第一批数：每轮接受的改动数、门 A 效果、确认集方向一致率、触发率。

判断：如果方向一致率明显低于 HarnessDev 的 53.1%，或几乎没有改动过门 A，先收窄搜索空间（只留 harness_params + 手册），再继续。

### 阶段 3：外环第一次（约 2 周）

用阶段 2 接受的规格产数据，走 4.4 的通道 1–3 + 学生自采 + 教师桥接，训 HI 再训 GIA，过门 B。同时做第一次 2×2 交叉搭配（{GIA@0, GIA@1} × {HI@0, HI@1}），得到协同项的第一个点。

判断：协同项 ≤ 0 且交叉搭配里"新 GIA + 旧 HI"比"旧 GIA + 旧 HI"还差，说明 GIA 在向伙伴过度适应，要加大通道 3 里教师 HI 报告的比例再试。

### 阶段 4：完整循环 r2–r4，路由器接管（3–4 周）

按 4.6 的时序每轮跑。并行跑消融臂（第 6 节 E1），同预算。RL 作为可选外环算子，最早第 3 轮接入，且只在 SFT 臂的曲线已经走平时才加，避免同时引入两个新变量。

### 阶段 5：收尾证据（约 2 周）

E4 正式版（植入缺陷，训练后系统）、E5 核验器报告、E6 内化、E7 迁移与适应曲线；最后一次性在 test 上跑所有臂的最终 checkpoint。

### 6.1 七个假设 **[09-28 已精简，见顶部修订表]**

| # | 假设 | 主要证据 | 通过标准（建议） |
|---|---|---|---|
| H1 | 完整循环比"只训练""只改 harness""纯蒸馏"在同预算下更好，且随轮次提升 | E1 主曲线 | 完整循环在 test 上显著优于三个消融臂；dev_confirm 上 r1→r3 不降 |

### 6.2 实验设计 **[09-28 已精简，见顶部修订表]**

**E1 主曲线（H1）。** **[修订]** 四臂：
- 完整循环；
- 只训练（内环关闭，规格固定在 r0，其余相同）；
- 只改 harness（外环关闭，权重固定在 r0 SFT）；
- **纯蒸馏**（同样的教师 token 和 GPU，教师直接多产数据训练，不跑循环）。

"人工迭代"臂只有在同预算重跑时才保留；旧的 r1–r8 历史教师、核验器都不同，不可比。r0–r3 至少四个点，曲线画在 dev_eval 上，最终在 test 上各测一次；检索一律用录制回放，测试时报告带/不带核查站点黑名单两组结果。预算按 `budget.jsonl` 对齐：GPU 时、教师 token、核验调用都要记。另把增益拆分到"教师 token"与"学生自采"两部分，回答审稿人"这只是蒸馏"的质疑。这就是 DESIGN §7 消融第 (6) 组，这里给了操作定义。

**E2 免训练 RSI 单独（H2）。** 对内环每个被接受的改动记录四个数：门 A 效果、dev_confirm 方向是否一致、在 test 运行里触发次数、换执行模型（Qwen3.5-4B / 9B / 27B / 教师）后方向是否一致。汇总成方向一致率、触发率、跨执行者一致率三个数，分别对标 HarnessDev 的 53.1%、18 个从未触发组件、执行者依赖。再按 RRSI 的口径把 dev（ID）与留出数据集（OOD）分开报。

**E3 两模型互助（H3）。** 两部分：

- 交叉搭配矩阵：GIA ∈ {底座, r_k, 教师} × HI ∈ {底座, r_k, 教师}。协同项 I = P(G_k, H_k) − P(G_k, H_0) − P(G_0, H_k) + P(G_0, H_0)，I > 0 说明两个角色一起升级的收益大于各自升级收益之和。和教师搭配的那一行/列用来区分"真变强"与"只是互相适应"：新 GIA 配教师 HI 也要不差。
- 训练方式消融（同数据量）：交替 + 互造数据（本方案）/ 各自只用教师数据独立训练 / 共用一套 LoRA（DESIGN 消融第 3 组）/ 关掉通道 2 课程。

**E4 路由器（H4）。** **[修订]** 主证据是**双干预**：每轮对前 3 格错误各做一个内环候选和一次针对性 LoRA 增量，实测哪根杠杆更有效，作为反事实最优杠杆；报告路由先验对它的预测准确率。植入缺陷测试作为补充：缺陷由项目外的人盲设计，要混入两根杠杆都能修的模糊缺陷，正确答案以双干预结果为准。下表是缺陷类型的示例：

| 类型 | 怎么植入 | 正确路由 |
|---|---|---|
| 规格缺陷 | 在 gia 规格里加诱导前提走私的措辞；在 hi 规格里删掉"上传日期≠拍摄日期"一类说明 | 内环，对应角色 |
| 能力缺陷 | 用少量故意带 wrong_citation 的数据微调学生 HI（教师不受影响） | 外环，HI |
| 核验器缺陷 | 关掉 anchored 层对某类数字的比对 | 核验器 |

报告定位准确率（角色 × 杠杆都对才算对）和修复轮数。然后在一个子集上比较预算分配方式：按路由 / 随机分配杠杆 / 总是内环 / 总是外环，同预算看提升。这个实验是"路由判据"这一贡献的主要证据，而且成本低，阶段 1 就能跑便宜版。

**E5 核验器（H5）。** 每轮报告：各错误类型的注入召回与人工精确率、人工与核验器一致性（κ）、exploitation rate。核心是相关性：把每个被门控评估过的改动（内环的规格候选、外环的 checkpoint）当一个点，x = 训练用核验器在 dev_select 上的分数变化，y = dev_confirm 上的原生指标变化，报告 Spearman ρ 与置信区间，并与"用模型自评代替核验器"的同一套点做对照（这就是 S³Gym 的设置）。 **[修订]** 只靠门控过程中的点，大约只有 20 个，彼此不独立，功效不够。所以另用冻结权重的内环专门生成 100–200 个随机或扰动的规格改动（包括明显变坏的），做剂量–反应分析（分层模型，按轮次、种子聚类）。核验器的精确率和召回率以人工金标集为准。

**E6 内化（H6）。** 对每个退役的手册条目 / 契约字段：内化前"挂着条目"的性能、内化后"不挂条目"的性能、内化后"仍挂着"的性能，三者对比，外加输入 token 变化。

**E7 迁移（H7）。** 沿用 DESIGN §7 的留出数据集与 0/20/50 条适应曲线，把"循环后的模型"与"只做 r0 SFT 的模型"都放进去比。

### 6.3 统计与报告

- 每个对比都是同一批案例上的成对比较：二值指标用 McNemar，连续指标用按案例的成对 bootstrap（10,000 次）给 95% 置信区间。Finding 级的证据链指标单元多，功效更高，适合作为主要过程指标。
- 训练臂至少 2 个 LoRA 种子，关键臂（完整循环、只训练）争取 3 个；推理每个案例 2 个种子。
- 样本量先用 r0 的方差算功效再定 dev_select / dev_confirm / dev_eval 的大小。粗估：150 个左右的成对案例、两臂结论不一致的案例约占两成时，大约能以八成功效看出 10 个点左右的准确率差异；5 个点级别的差异要靠 Finding 级证据链指标或加案例。
- 所有门控决策、被拒改动、失败的轮次都保留在 revision_log 里，论文附录全量报告，不只报好看的轮。

### 6.4 最小可发表证据集

如果时间或算力只够做一部分，优先保这四样，它们合起来就能支撑"RSI 在我们框架里有效"：

1. E1 至少三臂（完整循环 / 只训练 / 只改 harness）× r0–r3；
2. E3 的 2×2 交叉搭配与协同项；
3. E5 的核验分–提升相关性 + E2 的方向一致率；
4. E4 的植入缺陷定位。

## 7. 风险与退路

| 风险 | 表现 | 应对 |
|---|---|---|
| 轮数不够、曲线不单调 | r2、r3 回落 | 门 B 回滚保证不会越训越差；DESIGN §8 的退路不变：架构升为第一贡献，循环降为数据构造方法 |
| 门控集过拟合 | 门 A 通过、确认集不涨 | 门控只用 dev_select 与 dev_confirm，曲线只画在从不参与决策的 dev_eval 上；方向一致率本身就是监测指标；先做 A/A 测试量出门的假接受率 |
| 角色间过度适应 | 新 GIA 只配新 HI 好 | E3 里与教师伙伴交叉；通道 3 保留一定比例教师报告 |
| 核验器被钻空子 | 训练用核验分涨、参考核验器与人工不认 | verifier_ref 冻结；exploitation rate 每轮报；超过阈值暂停内环 |
| 学生自采数据导致塌缩 | 输出多样性下降、格式塌缩（Aspire 见过） | 固定比例复习 r0 教师数据（09-11 方案的 80/20）；监控动作类型分布与重复输出率 |
| 概念被抢先 | Co-Harness 出多智能体版本 | 论文差异点放在真值核验与路由判据上，不放在"多智能体"标签上；尽快把 E4 的便宜版做出来 |
| 算力 | 8×A100 分时给教师、学生、训练 | 内环只用学生推理，便宜；外环每轮一次；RL 只在 SFT 曲线走平后才加 |
