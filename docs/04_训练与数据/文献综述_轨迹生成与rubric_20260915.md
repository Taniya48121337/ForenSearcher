# 文献综述：轨迹生成与 rubric 设计（2026-09-15）

目的：为 `数据生成框架审计_20260915.md` 第四节的重构方案找更强的机制来源，并确认哪些空间还没被占。范围：2025-06 至 2026-09 的 arXiv 工作，两条线各约 20 篇。两份原始综述附在本文末尾（含全部链接）；这里先给结论。

## 一、值得直接采用的机制（按对本项目的重要性排序）

### 1. 证据消融式对照（REAL 2609.08943 + Divide-and-Cooperate 2606.10684 + CaRR 2601.06021）

大白话：把老师傅办案时桌上的某一份证据抽走，再让他重办一次同一步，看结论会不会跟着变。结论跟着变，说明他真的在看证据；结论不变，说明他在编。REAL 就是靠这种"逐轮删证据"发现很多模型"准确率高但根本不依赖证据"。

落到本项目，在证据库（store）上做三类程序化扰动，每类扰动**事先就知道正确结论该怎么变**，所以不需要让模型来出负例：

- 删除/屏蔽：把某条被核验为"支持"的 Finding 所引用的 E 从 HI 可见范围移走。期望：该 Finding 消失或报告降为 INCOMPLETE；若模型仍写出这条 Finding → 得到一条 `unsupported_assertion` 负例。
- 替换/错位：把 E 的内容换成结论相反或口径不同的版本，或把 E3 的内容放到 E5。期望：Finding 改为"矛盾"或引用改编号；不变即 `wrong_citation` / `attribution_drift`。
- 加噪（硬正例）：往证据库塞 3–5 条同话题不同事件的弱相关 E。期望：结论和引用都不变；HI 引用了噪声 E 或 GIA 因此不敢结束 → 分别记两类错误。

每次扰动产出 `{state_ref, perturbation, expected_delta, observed, error_type}`。它同时是对照训练对，也是核验器的校准集，替代现在手写的 12 条。

### 2. 反向线索评分（ABSeeker 2608.05102 + EviPath 2509.23071）

大白话：从标准答案倒推出"办这个案子必须拿到哪几份证据"，然后给每一步打分：这一步有没有新拿到一份必需证据。这样"多余的动作""不针对缺口派任务""不必要的轮次"三类错误都有了程序性定义，不用等 RL，SFT 阶段就能按步加权。ABSeeker 用这个思路让 4B 模型用 8.5K 样本追平 30B。

本项目的证据链 `答案 → Finding → E → 来源` 天然就是线索图。每个案例在 `cases/` 里记"必需 E 集合"（来自数据集标注，或教师首次成功 run 经核验后的证据链）。冷启动可用 EviPath 方式先把证据灌进 store 让教师只写拆解和报告，但这类样本必须标 `abductive`、不用于 SEARCH 动作监督。

### 3. 同状态对照对 + 承诺点 + 学生续跑门槛（Agentic-DPO 2607.10601、CAR 2606.08275、FutureBridge 2608.01953）

大白话：对照对不是"两条完整轨迹"，而是"同一张桌面、两种决定"。先找出案子是从哪一步开始走偏的（CAR 的"承诺点"：重采样这一步会改变结果的最后一步），只在那一步让老师傅按新版说明书重做；老师傅给的好后缀还得让实习生自己接着往下走一段、核验分确实上升才入库（FutureBridge），避免教实习生学不会的招。负例优先用实习生自己在该状态的采样（Agentic-DPO），这样负例分布和训练目标一致。同一桌面用 ≤8K / ≤16K 两档渲染各出一份（Agentic-DPO 的 PPA），渲染档写进 metadata——把"渲染变体"从混淆变量变成扩增。

### 4. 引用感知的三态核验（CaRR、CuRe 2607.05150、Rulers 2601.08654、Mind2Web 2）

大白话：每条 Finding 当作一句断言；核验器必须重新读证据原文或看像素，给出"支持 / 矛盾 / 找不到"三态，并把原文里那句话摘出来（quote），摘不出来就不算支持。CaRR 把这个做成了 RL 奖励，比只看最终答案的奖励更好、更能压捷径。核验模型必须和教师分开，而且不给它演员的 history 渲染，只给 Finding、E 原文和任务（Inertia 2608.23045 实证：模型评自己产出的东西比评外来的更不客观）。

### 5. 三层 rubric（ExecRubrics 2608.22559 / RLCF 2507.18624 / ARCO 2606.21262 / REVEAL 2608.08612）

第一层程序可验证、零 LLM、任一失败即一票否决：E 存在、引用 E 与 Finding 同案例、COMPLETED 时 findings 非空且任务要求项全覆盖、来源政策遵守、数值日期在所引 E 原文可定位、GIA 同轮任务互不依赖。第二层证据锚定的模型评判，即第 4 条。第三层过程与充分性：以轨迹前缀为条件的步级标准（ARCO），报告前"还缺什么线索"的充分性门（REVEAL）——`completed_without_finishing` 和 `premature_finish` 本质是充分性核验缺失。

权重规则：负权只扣不入分母（ResearchRubrics 2511.07685）；absence 型条目（"不得……"）要占多数——Scale AI 的 2605.12474 发现 presence 型条目会让模型学会"话题近似""部分满足"这些作弊，事实正确性反而下降。反作弊再加两招：Rubric Dropout（2608.11669，每步随机丢 30–50% 条目再算分，防止只学"引用格式对"）；每轮用另一个核验器抽检新增"通过"条目，算 exploitation rate 写进 gate。

### 6. rubric 自己也进循环（Rubicon 2508.12790、CARE 2609.00892、Rubrics on Trial 2607.15092）

Rubicon 的做法是离线把异常高分的回答拿出来归纳作弊模式，写成"防御条目"注入下一轮——这就是 diagnose → revise 的 rubric 版。新条目不能想到就加：必须能区分至少 N 对对照样本、且不奖励表面风格（Rubrics on Trial 的"审判"），才允许入库。写条目的人先读证据库再写（Agentic Rubrics 2601.04171）。

### 7. 诊断映射到生成器的哪一段 + 每轮只改一个模块（ODE 2605.10832、ModularRSI 2609.14857）

ODE 在当前被训策略的 rollout 上按 rubric 诊断，把失败映射到"任务生成器的哪个阶段"，改数值参数或追加拒绝规则，并把任务按 `too_easy / good_match / too_hard / fake_hard / infra_failure` 分档只取 good_match。ModularRSI 的结论是逐模块修改优于联合修改。对应本项目：`diagnose/` 输出每类错误绑定到规格的哪一段（teacher_instruction 的哪条 / harness_params 的哪个参数 / 案例池的哪个 family），每轮只动一个；`fake_hard`（核验器无法核验的案例）退回 cases/ 修标注。

### 8. 环境噪声课程（NoisyAgent 2605.27209）

程序化注入 SEARCH 空返回、页面截断、抽帧失败，比例从 10% 起随学生"正确报 INCOMPLETE"的比率上升而加大。期望行为固定（报 INCOMPLETE 且不编造 E），错误落 `completed_without_finishing` / `fabricated_evidence_id`。

## 二、明确不采用或谨慎的

纯自博弈出题（SESA、Search Self-play）：视频核查的真值依赖真实篡改样本，出题者造不出可验证的视觉证据，只能用于文本侧 GIA 拆解。MCTS 树搜索轨迹：每步 INSPECT 成本高、状态含像素，用承诺点重采样替代全树。AgentHER 式"失败轨迹重标目标"：只能在 HI 子任务层用且需核验器复核，不能重标最终核查结论。摘要式经验/技能记忆：2601.22436 证明模型常忽略摘要经验，本项目走参数训练路线不作主线。参数训练本身的负迁移（S³Gym、Aspire 都报告）：正是"核验分↔留出提升相关性"门控的动机，写成论文里的明确指标。

## 三、还没被占的空间（本项目的差异化落点）

1. **rubric 条目本身引用证据编号，可重放。** 现有 rubric 都是任务级或步级文本，核验时才去找证据；本项目 store 编号稳定，条目可以写成"F3 的 12.4% 必须出现在 E7 第 2 页"，即条目就是可执行断言，而且同一条目在 spec@v 和 v+1 对同一 episode 的判定应一致，不一致就是 rubric 漂移。Mind2Web 2 绑 URL 但每次重抓不可重放；文献未见此设计。
2. **教师 / 核验器 / rubric 作者三角分离，以留出集真实提升作为 rubric 修订的接受准则。** 共演方法（ARCO、EvoRubrics、CARE）靠外部参考 judge 或随机掩码抗作弊；S³Gym 只诊断相关性没做成门。
3. **跨迭代 rubric 漂移追踪。** Rubric-RL 综述（2608.27505）把"语义漂移"列为开放问题无方法。冻结一组 episode（含注入错误的校准样本），每次升版重跑核验，报告各错误类判定翻转率与 presence/absence 比例变化，超阈值回滚。
4. **多模态细粒度错误的半程序化核验。** `misread_fine_text`、`sloppy_numeric` 在 CuRe/REVEAL 中不存在；对引用帧做 OCR / 裁剪放大再比对，把它们从模型评判降级为半程序核验。
5. **一个错误枚举同时驱动核验、对照生成和 rubric 条目。** 错误注入器既校准核验器又生成负例，Rubicon 的防御 rubric 只是文本，没有这个闭环。

风险提示：CARE、ARCO、EvoRubrics、Rubric Dropout 都在近三个月出现，"rubric 共演 / 反作弊"赛道拥挤；差异化必须落在"证据编号可重放 + 三角分离 + 漂移门控"，而不是再提一个共演算法。

## 四、对审计文档第四节方案的修订

原方案的 `datagen/{errors, specs, cases, run, verify, diagnose, revise, export, gate}` 骨架不变，加入以下具体机制：

- `cases/case.json` 增加 `required_evidence`（必需 E 集合，含来源与定位）和 `checks[]`（程序化断言）。
- `revise/contrast.py` 的三种生成方式改为：证据消融（删/换/加噪）、承诺点重生成 + 学生续跑门槛、环境噪声注入；错误注入器同时产出核验器校准集。
- `verify/` 拆成 `checks_exec.py`（第一层，veto）、`checks_llm.py`（第二层，三态 + quote + method）、`sufficiency.py`（第三层）；核验模型 ≠ 教师，上下文隔离。
- `specs/*.yaml` 的 rubric 条目带 `axis: presence|absence`、`evidence_refs`、`replayable: true`，并有一组冻结校准 episode 用于漂移检测。
- `export/` 每步写 `clue_gain`（该步新增的必需 E 数）用于 loss 重加权；同状态两档渲染各出一份。
- `gate/` 新增 `exploitation_rate`、`presence_absence_ratio`、`rubric_flip_rate`，与 `direction_agreement`、`verifier_score_vs_heldout_gain` 并列。
