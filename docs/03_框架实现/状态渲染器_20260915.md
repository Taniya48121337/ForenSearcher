# 状态渲染器：把送给模型的"桌面"压到 8K / 16K 两档（2026-09-15）

位置：`src/foren_searcher/state_render.py`；接线在 `store/records.py`（`MemoryPolicy.state_renderer`）、`hi/workspace.py` 与 `gia/runner.py`（写进 `runtime_constraints.state_renderer`）、`local_models._generation_messages`（真正压缩的地方，本地模型和 OpenRouter 共用）、`config.py` 与 `configs/*.toml`（`[runtime].state_renderer`）。测试 `tests/test_state_render.py`（15 项）。

## 为什么要做

审计时量过：每一轮送给模型的输入平均 2.5 万字符、最长 7.6 万，而训练一行 ≤8K token 的只有 47 条、≤16K 的 219 条（共 303）。大头是三样重复的东西：每轮原样附上的工具参数 schema（6.6K 字符，永远一样）；历史里每一步搜索结果的完整快照（每步 6–9K，模型其实只需要"当时搜了什么、拿到哪些 R/E"）；证据正文在 GIA 报告附件里的整页复制。不解决这个，学生模型要么训不动，要么训练时看到的是被硬砍过的半截输入。

## 做法（大白话）

同一份"桌面"，按档位重新排版，编号一个不丢：

- 工具清单：schema 换成一行签名，如 `SEARCH {input_type:text, query:string, output_type:text|image|video} | {source:string, …}`。6.6K → 1.7K。
- 证据卡片、候选卡片：每张一行，如 `E7 [image] 视频E1在14.133秒的帧 ← E1 (INSPECT/get_frames)`、`R9 page: 标题 — url — 摘要`。去掉 record_type、空字段，浮点数保留 3 位小数。
- 历史步：只留动作、参数、items 摘要行和最小 details 摘要（READ_RECORD 留编号 + 页码 + 160/240 字摘录；INSPECT 留操作、状态、结果编号、反馈；SEARCH 只留 stop_reason）。完整 results 不再重复。
- 最新一步（latest_observation）：保留 details，正文按档位截断（8K 档 3000 字、16K 档 6000 字），截断处写明 `…[已截断 N 字符；READ_RECORD 可读全文]`；搜索结果每条只留候选编号、标题、摘要、产生的 E、失败原因。
- GIA 报告附件（supporting_records）：16K 档留 1200 字正文摘录；8K 档只留一行卡片，正文靠 READ_RECORD。
- 还超预算时按"可恢复优先"丢：先丢最旧的历史步（读过焦点证据的步最后丢），再丢候选卡，再把最新观察正文减半（最多三次），再丢非焦点证据卡，最后附图只留编号、视觉摘要只留已观察区间。凡是丢过东西，`context_truncated=true` 告诉模型"历史不完整"。任务、材料、最新观察本身就装不下的，直接报错，不静默硬砍。

渲染是纯函数：不改 Store 里记录的 model_view，不改 OpenRouter 用来生成输出 schema 的原 payload；同一输入 + 同一档位 = 同一输出，训练导出时可以从记录的 `model_input` 事件重放，所以档位名会随每行数据的 metadata 走。

## 在 340 行试点语料上的实测

user 侧字符（不含 system prompt，含 `_generation_messages` 追加的约 2K 常量说明）：

| | legacy p50 / p90 / max | compact_16k | compact_8k |
|---|---|---|---|
| HI（303 行） | 23.1K / 43.1K / 72.5K | 11.3K / 17.3K / 22.9K | 10.2K / 12.8K / 13.3K |
| GIA（37 行） | 24.9K / 40.5K / 54.0K | 18.5K / 26.3K / 26.9K | 10.7K / 13.8K / 14.1K |

16K 档：HI 303 行零丢历史；GIA 3 行标了截断。8K 档：HI 40 行丢了部分历史（共 115 步），GIA 9 行标了截断，全部 340 行都能装下。可见的 E/R/C/F 编号（证据卡、材料、焦点、附图、报告 findings）在两档下全部保留；唯一的例外是 8K 档 GIA 的旧轮次索引 `history_index` 超过 12 条时只留最近 12 条（有"另有 N 条"标记）。

按试点语料 1 token ≈ 1.7 字符算，8K 档整行（含 3.8K 字符 system）约 8–10K token，16K 档约 9–16K token。"8K"是目标不是硬保证；剩下的常量说明文字下一版规格会挪进 student_prompt，那时再收紧预算。

## 配置

`configs/local.toml` 用 `compact_8k`，`configs/server.toml` 用 `compact_16k`，`MemoryPolicy()` 默认仍是 `legacy`（旧行为不变）。规格目录的 `harness_params.state_renderer` 目前只是记录；等 `datagen/run` 落地后由规格驱动运行时，配置里的值作为覆盖。
