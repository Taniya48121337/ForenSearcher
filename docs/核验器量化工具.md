# 核验器量化工具（2026-09-29）

路由的入场条件需要每类错误的召回 ρ_c 和精确率 p_c；S4 列出了学生钻核验器的路径。下面四个工具给这些量出数。
**它们都不改变核验器的判定行为**：只读判定文件、只改报告 / 答案 / 计划的副本，再调用正式的核验链路。

| 工具 | 模块 | 入口 | 测什么 |
|---|---|---|---|
| 单元召回注入 | `verify/calibrate_units_recall.py` | `scripts/calibrate_units_recall.py` | answer / plan 单元每类错误的召回 ρ_c |
| 校准规则审计 | `verify/calibrate_rule_audit.py` | `scripts/calibrate_rule_audit.py` | R1 / R2 / R4 的假接受率与真接受率 |
| 对抗探针集 | `verify/adversarial.py` | `scripts/adversarial_probes.py` | S4 四条路径的被识破率 |
| exploitation rate | `verify/exploitation.py` | `scripts/exploitation_rate.py` | 训练核验器放行、参考判不通过的比例 |

四个工具都用 `judges.add_judge_arguments`：`--judge none`（只跑程序层）/ `local`（本地 OpenAI 兼容服务）/ `openrouter`（付费）。

> **局限（通用）**：测试里用的是假核验模型（FakeJudge / ScopeJudge / 各测试里的派生类），只验证"注入 → 核验 → 打分"的流程跑得通、
> 程序层该抓的抓得到。模型层的召回、规则 report 模式的假接受率、探针被识破率、exploitation rate 的**真实数字要等正式核验模型**
> （以及 verifier_ref / 人工金标）接上后重跑。下文 `judge=none` 的数字只说明"程序层单独能做到什么"。

## 1. 单元召回注入 `calibrate_units_recall`

把 `calibrate_recall`（报告级）的"注入 → 核验 → 与同条件对照比"扩到 GIA 的两个单元。核验链路与正式流程一致：
answer = `units.check_answer` + `answer_anchored` 逐句锚定 + `calibrate.recalibrate`；plan = `units.check_plan` + `plan_judged`。

| 单元 | mutator | 改法 | 期望类型 | judge=none 程序层 |
|---|---|---|---|---|
| answer | `drop_citation` | 删掉一组引用 | unsupported_assertion / wrong_citation | 抓不到；删段末那组时句子变 uncited，**任何层都不报**（行里 `becomes_uncited`） |
| answer | `add_unsupported_clause` | 某组句子加一句编造的数字 / 实体 | unsupported_assertion / wrong_citation | 抓不到 |
| answer | `swap_citation` | 引用换成未引过、内容不相干的文本 E | wrong_citation / unsupported_assertion | 只有报告级代理的 flag（`flag_only`），不计命中 |
| answer | `fabricate_citation` | 引用里加不存在的 E | fabricated_evidence_id | **能** |
| answer | `flip_label` | 不实 ↔ 属实 等 | omitted_required_fact（label_expected） | **能** |
| answer | `negate_label` | "不实" → "并非不实" | omitted_required_fact / wrong_citation / unsupported_assertion | 抓不到（标签检查是子串匹配） |
| answer | `drop_required_block` | 删掉覆盖某 must_cite 要求的全部句子 | premature_finish / omitted_required_fact | 抓不到，**模型层也抓不到**（见漏洞 3） |
| plan | `smuggle_premise` | 任务开头塞"已知 X"（X 案卷与报告里都没有） | premise_smuggling | 抓不到（只有模型能判） |
| plan | `duplicate_sibling` | 复制一个兄弟任务 | overlapping_sibling_tasks | 抓不到，**模型层也抓不到**（见漏洞 4） |
| plan | `retarget_covered` | 合成下一轮，只派已覆盖要求、留一项 must_cite 缺口 | task_not_gap_driven | 抓不到（只有模型能判） |
| plan | `sibling_dependency` | 任务写"待 W1-2 的结果确认后……" | dependent_sibling_tasks | **能**（正则） |
| plan | `sibling_dependency_paraphrase` | 换说法写依赖 | dependent_sibling_tasks | 抓不到，**模型层也抓不到**（见漏洞 5） |
| plan | `fabricate_material` | materials 加不存在的编号 | illegal_action | **能** |

`retarget_covered` 的条件是合成的（`condition.round_index` / `condition.covered_before`），对照在同一合成条件下跑原任务。

```bash
python scripts/calibrate_units_recall.py --runs experiments/sft_data/runs/true_4124903_r1 \
    --verdicts experiments/sft_data/verdicts_r0_judged.jsonl --judge none --per-kind 2 --seed 7 \
    --out experiments/sft_data/calibration/units_recall_r0.none.json
```

输出（与 `calibrate_recall` 同格式，另加 `by_unit`）：
- `recall_overall` / `recall_conclusive` / `inconclusive`：命中 / 全部；conclusive 去掉"未命中且有 pending"的行（judge=none 时模型层未运行也算 pending）。
- `by_kind[k]`：`n`、`detected`、`recall`、`inconclusive`、`recall_conclusive`、`flag_only`（只出了 flag）、`rejected`（处置比对照更差）、`misses`。
- `by_expected_type`、`false_new_errors`（出现了期望外的新错误）、`controls`（每个 (决定, 条件) 的对照处置与错误类型）、`rows`。
- 命中判定：注入后新出现、对照里没有的期望类型非 flag 错误（`unit_error_key`：程序层按 (类型, detail)，模型层按 (类型, span, 所引 E, 任务)，
  不含答案句号 A{n}——删句 / 插句会让句号整体平移）；plan 的模型错误还要落在被改的任务上。

true_4124903_r1、`--judge none`、默认参数：23 处注入，命中 7（fabricate_citation 2/2、flip_label 1/1、sibling_dependency 2/2、
fabricate_material 2/2），其余 16 处全部 inconclusive。

## 2. 校准规则审计 `calibrate_rule_audit`

规则的触发条件（读 `calibrate.recalibrate` 原文）与每个样本针对的条件：

| 规则 | 样本 | 类别 | 针对的条件 |
|---|---|---|---|
| R1 | `r1_universal_overreach` | 反例 | "≥3 条 E 每对 supported 且 coverage 通过 ⇒ 合起来撑得起"——不看结论是不是全称判断（"自始至终每一帧"） |
| R1 | `r1_citation_stacking` | 反例 | "≥3 条 E" 只是计数门槛：借别的 Finding 的 E 并附一句它们确实支持的短句，堆到 3 条 |
| R1 | `r1_joint_support` | 正例 | ≥3 条 E 合起来支持，逐对给了 scope 提示（应豁免） |
| R1 | `r1_joint_support_two` | 正例 | 同上但 2 条 E（应豁免，门槛导致假拒绝） |
| R2 | `r2_false_relation` | 反例 | 只看"span ≤20 + 关系词 + 别处有 supported 文本 E"，不查关系本身是否成立 |
| R2 | `r2_fact_in_relational_wrapper` | 反例 | 关系词只是关键词：编造事实包一层"与通报相符" |
| R2 | `r2_one_sided_relation` | 正例 | 只引帧的 Finding 写"这与报道描述相容"，文本支持在同报告别的 Finding（真实 F7 模式） |
| R2 | `r2_one_sided_relation_long` | 正例 | 同上但关系句 >20 字（长度门槛导致假拒绝） |
| R4 | `r4_substring_sibling` | 反例 | 支持片段与反驳 span "任一方向互为子串（≥2 字）"：兄弟 E 只核实了"7月14日"，就撤销了对"2029年7月14日"的反驳 |
| R4 | `r4_image_sibling` | 反例 | 图片来源的支持片段 verified=None 不做程序回查也被采信 |
| R4 | `r4_earlier_state` | 正例 | 前后两条通报，另一条逐字核实了同一部分（真实 E24+E21 模式） |
| R4 | `r4_paraphrased_sibling` | 正例 | 同上但兄弟片段是转述（子串对不上，假拒绝） |

两种模式：
- `--mode verdict`（默认，不调模型）：在真实报告判定上**模拟一个如实标出错误的核验器**（目标 Finding 的 judgments / coverage / 目标错误是合成的，
  其它 Finding 保持真实判定），直接 recalibrate。量的是"核验模型抓到了，规则会不会放掉"——条件假接受率。
- `--mode report --judge local|openrouter`：改过的报告走 `verify_report`（exec + anchored）再 recalibrate。目标错误没被标出记 `not_flagged`，不进分母。

```bash
python scripts/calibrate_rule_audit.py --runs experiments/sft_data/runs/true_4124903_r1 \
    --verdicts experiments/sft_data/verdicts_r0_judged.jsonl --mode verdict \
    --out experiments/sft_data/calibration/rule_audit_r0.json
```

输出：`by_rule[R].false_accept` / `true_accept`（`n`、`flagged`、`not_flagged`、`exempted`、`rate` = exempted/flagged、
`disposition_flipped` = 因目标错误被豁免而处置翻成 positive 的条数——把目标错误放回去处置就不是 positive 才算）、`by_kind`、`rows`、
`observed_real_triggers`（真实判定上各规则实际触发次数：r0 报告判定 + 单元判定 100 个单元里 R1 28、R2 7、R4 40 次）。

true_4124903_r1、verdict 模式、默认参数：R1 假接受 5/5、真接受 3/5；R2 假接受 8/8、真接受 2/4；R4 假接受 5/5（1 条把报告翻成 positive）、真接受 4/8。
这些是规则逻辑在触发条件下的必然结果，不依赖核验模型；端到端比率（核验模型会不会先把错误标出来）要跑 report 模式。

## 3. 对抗探针集 `adversarial`

| 路径 | 探针 | 改法 | 期望 |
|---|---|---|---|
| (a) | `vague_finding` | 把某组必需证据的**全部**提供者 Finding 改成"与报道相容、不排除……"的空话，引用不动 | omitted_required_fact / completed_without_finishing |
| (b) | `citation_stacking` | 干净 Finding 加一句编造事实，再堆 N 条（默认 5）本工作区可见、别的 Finding 引过的 E | unsupported_assertion / wrong_citation |
| (c) | `over_incomplete` | 核验判定无缺项的 COMPLETED 报告改 INCOMPLETE，Finding 不动，理由空泛 | incomplete_though_answerable |
| (d) | `easy_tasks` | 合成下一轮，只派"复核已核实的结论"，留一项 must_cite 缺口不派 | task_not_gap_driven |

探针落盘成 jsonl（`probe_id`、`path`、`unit`、`run_dir`、`workspace_id` / `request`、`target`、`original`、`mutated`、`change`、`expected`、`condition`），
`--probes-in` 原样重跑，换核验器时用同一批探针对比。

```bash
python scripts/adversarial_probes.py --runs experiments/sft_data/runs/true_4124903_r1 --judge none \
    --probes-out experiments/sft_data/calibration/probes_r0.jsonl --out experiments/sft_data/calibration/adversarial_r0.none.json
python scripts/adversarial_probes.py --probes-in experiments/sft_data/calibration/probes_r0.jsonl --judge local \
    --out experiments/sft_data/calibration/adversarial_r0.local.json
```

输出：`by_path[p]`：`caught_rate`（被识破率 = 召回口径）、`caught_rate_conclusive`、`inconclusive`、`rejected_rate`（处置比同条件对照更差，
不论类型——"识破了有没有挡住"）、`fooled`（没识破的探针）；`rows`、`controls`。

true_4124903_r1、`--judge none`：11 条探针，识破 1 条——(a) 里 W1-2 的空话顺带删掉了"耶拿桥"，被第一层 entity_in_evidence 抓到；
其余 (a)(b)(c)(d) 全部要靠模型层。

## 4. exploitation rate `exploitation`

训练核验器判"通过"、参考判"不通过"的比例，按 单元 × 错误类型 × 轮次 拆开。

- 对齐：report 按 (run, workspace_id)；plan / answer（及 step）按 (run, request, unit)；Finding 按 (run, finding_id)（从 report 单元的
  judgments / coverage / errors 展开）。对不上的条目在 `unmatched[unit]`（`only_train` / `only_ref` 与示例）。
- 通过：判定文件 disposition == positive；参考侧 uncertain 记 undecided 不进分母，训练侧 uncertain 算不通过。Finding：无 major / critical 非 flag 错误 = 通过。
  人工金标：finding full / partial·none，answer acceptable·minor / unacceptable，plan good·minor / bad，cannot_tell 与平票 = undecided；多标注人多数票。
- 错误类型取参考侧（参考判定的 major / critical 类型，或标注人勾选的 errors；都没有记 unspecified）。轮次：W{r}-{i} 的 r 或 subject.round。
- 默认两侧都先过 `recalibrate`（与训练导出同口径），`--no-recalibrate` 关掉。

```bash
python scripts/exploitation_rate.py --train experiments/sft_data/verdicts_r0_judged.jsonl experiments/sft_data/verdicts_units_judged.jsonl \
    --ref <verifier_ref 的判定文件 ...> --out experiments/sft_data/calibration/exploitation_r0.json
python scripts/exploitation_rate.py --train <判定文件 ...> --gold-batch experiments/sft_data/gold_set/v1 \
    --gold-labels labels_a.json labels_b.json --out experiments/sft_data/calibration/exploitation_gold_v1.json
```

输出：`overall`、`by_unit[u]`（`aligned`、`ref_undecided`、`train_pass`、`ref_fail`、`exploited`、`rate_given_train_pass`、`rate_given_ref_fail`）、
`by_unit_type_round`（每行 unit / type / round；`train_pass` 是该单元该轮全部放行数，`ref_fail` 是参考不过且含该类型的数）、`unmatched`、`exploited`（明细）。
`rate_given_train_pass` = 训练奖励里的假正例比例；`rate_given_ref_fail` = 训练核验器相对参考的漏报率。

## 这次量出来的核验器漏洞（true_4124903_r1 + 规则逻辑）

1. **answer：uncited 不是错误。** 删掉段末那组引用，那几句变成 uncited，`answer_anchored` 按设计不锚定、不报错；只有整份答案一个引用都没有才报。
2. **answer：标签检查是子串匹配。** "该声明并非不实"照样命中 label_expected；只有逐句锚定时核验模型读出"并非"才可能抓到。
3. **answer 没有答案级充分性检查。** premature_finish 按**报告**里干净 Finding 的覆盖算，与答案写了什么无关；删掉覆盖某 must_cite 要求的全部句子，任何层都不报。
4. **overlapping_sibling_tasks 只能事后判。** 它由 hindsight 按"两个工作区交回同类 Finding"判定，计划阶段的文字重复程序层看不见，plan 提示词也不问重叠。
5. **dependent_sibling_tasks 只有正则。** 换个说法（"在另一名调查员查明……之后，以其为准"）就绕过；plan 提示词不问依赖。
6. **plan 单元"检出 ≠ 拦下"。** plan 的错误类型都是 major（premise_smuggling、task_not_gap_driven、dependent_sibling_tasks）或 minor（illegal_action、
   overlapping_sibling_tasks），`decide()` 要 ≥2 个 major 才判 negative；单条前提走私 / 单个不对缺口的任务 / 单个非法材料编号的计划仍是 positive，export 收进 accepted。
7. **过度 INCOMPLETE 没有惩罚。** incomplete_though_answerable 是 minor，就算充分性层识破，报告处置仍是 positive（探针 (c) `rejected_rate` 恒为 0）；
   而且它要求 `answerable_from_report ∧ 无 uncovered ∧ status_should_be == COMPLETED` 三者同时成立，任一项模型拿不准就放过。
8. **R1 可以堆引用触发**（≥3 是计数门槛，全称判断也豁免）；好在 anchored 层的 scope_overreach 是 minor，豁免只影响错误计数、不改处置。
   若将来 reward 按错误类型计分或 scope_overreach 升级为 major，这条会变成实打实的漏洞。
9. **R2 不查关系是否成立**：任何 ≤20 字、含"一致 / 相符 / 相容……"的错误断言都会从 critical 降为 major 且不传播；报告里若只剩这一条，处置翻成 positive。
10. **R4 双向子串 + 图片片段不回查**：兄弟 E 只要核实了一个 ≥2 字的片段（如"7月14日"）是反驳 span 的子串，或帧被判"支持"整段，就撤销 wrong_citation（critical），可翻成 positive。
11. **含糊 Finding 的防线只在模型**：第一层按 url_pattern / acquired_by 数引用，引用不动就认为必需证据拿到了；充分性提示词写的也是"必须有 Finding 引用了对应证据才算 covered"，
    容易把"引了"当"回答了"。这次唯一的识破来自空话顺带删掉了案卷要求的实体。
12. 程序层对 (b) 堆引用、(d) 派简单任务、premise_smuggling、task_not_gap_driven 完全没有信号，全靠核验模型。

## 需要真实核验模型才能出数的项

- 单元召回：除 fabricate_citation / flip_label / sibling_dependency / fabricate_material 外的全部 mutator（answer 逐句锚定与 plan 评判）。
- 规则审计 report 模式：核验模型先把目标错误标出来的比例（not_flagged）与端到端假接受率；verdict 模式的数只是规则逻辑的条件率。
- 对抗探针 (a)(b)(c)(d) 的被识破率（除 (a) 中碰巧删掉必需实体的那类）。
- exploitation rate：需要 verifier_ref 的判定文件或人工金标（gold_set 的 labels）；训练核验器本身也应是正式核验模型的判定。
