## 0. 一句话结论

这个项目实际上有三样东西是真的：一套能跑通真实任务的调查框架代码（GIA + HI + SEARCH/INSPECT，约 1MB 源码、90 个测试文件），一份与代码基本一致的设计定案（交接文档第 9–23 节），以及一个用 Codex CLI 当教师、跑了 50 次真实调查、筛出 826 行候选 SFT 数据的构造试点。**没有做过的事：任何一次模型训练、任何一次独立人工标注、任何一次可以称为"实验结果"的对比。** 论文层面目前只有假设，没有证据。

其余的一切——七十多个 `.pytest-*` 目录、1200 个 `tmp/` 文件、140 个 `outputs/*` 目录、25 个 `student_inputs_*` 目录、五种模型口径、三种互相矛盾的"SEARCH 状态"——是 vibe coding 留下的泥沙，需要清掉，但不影响上面三样东西的价值。

## 1. 项目现在到底在做什么

用交接文档第 6 节的原话："以 Harness-1 为运行底座，研究异构视频核查任务是否共享一组可学习、可组合的基础调查能力，并构建一个能够通过动态调查完成来源检索、片段定位、差异分析、篡改归因和事实核查的统一 Deep Research Agent。"

落到系统上，只有两个需要训练的角色：

**GIA（Global Investigation Agent）** 看全局任务，每轮决定派几个并行的调查任务（`INVESTIGATE`），或者认为证据够了直接作答（`FINISH`）。它不碰工具。

**HI（Harness Investigator）** 在一个独立的 Workspace 里执行 GIA 派下来的一个任务，每一步选 `SEARCH` / `INSPECT`（`DETECT` 只有接口壳），最后提交一份 `COMPLETED` 或 `INCOMPLETE` 的 Workspace Report。所有 Workspace 共享同一个 HI 参数。

两者之间的运行结构叫 **DIR（Dynamic Investigation Rounds）**：轮内并行、轮间串行；Workspace 不能生子 Workspace；已提交的证据 E 对同一次调查的所有 Workspace 可见，但 Finding 和报告只交给 GIA。证据链是 `Final Answer → Finding(F) → Evidence(E) → Source(R)`。

这个定案是清晰、自洽的，而且代码确实是照它写的。交接文档第 23 节列了 22 条"已否定、不要再引入的设计"，这份清单是你以后对着任何新想法先检查的基线。

## 2. 时间线：这一个月发生了什么

按文件修改时间还原，项目经历了五个阶段，前两个已废弃。

**阶段 A（08-16 ～ 08-17）：两条已放弃的论文思路。** `step1.md`–`step7.md`、`allinone.md` 是围绕一个叫 "ClaimUnitTest / Claim-Causal Mutation-Tested Trajectory Compilation" 的方法做的查新流程，结论是与现有工作高度重叠。次日的 `ECSO_HIERARCHICAL_ACTION_TREE_20260817.md` 是一个 6 分支 × 12 动作 × 52 叶子工具的"证据义务树"。这两条思路后来在交接文档第 8 节和第 23 节里被明确推翻。`claimunit_video_sham_1004/`、`ideaspark_run/`、`novelty-checks/`、`literature-review/` 都属于这一阶段。

**阶段 B（08-24 ～ 09-03）：与 GPT 反复讨论，收敛出定案。** 271KB 的交接文档记录了至少七次方案转向（自建 SLEUTH-V 基准 → EVID-Bench + Harness-1 → VideoSearcher 适配 → 扩宽为异构核查 → Working Memory Tree → **GIA + DIR** → 工程实现细节）。08-26 初始化了 git，但 `.git/index` 只有 1KB，几乎没有提交过。

**阶段 C（09-01 ～ 09-09）：写代码 + 用 OpenRouter 上的 Qwen3.8-27B 跑真实任务。** `src/` 的全部模块在这九天内产生。`outputs/` 下 140 个 `*-validation` / `*-review` 目录是这一阶段一次次定向验证的残留。09-09 的审查报告结论："四项当前网页任务流程均完成，三项主结论通过，四项严格答案均有未通过项。"离线回归 952 项通过，预算 $24 用了 $13.64。

**阶段 D（09-10 ～ 09-13）：SFT 数据构造试点。** 09-11 写了训练方案（Qwen3-8B × 2 LoRA、交替 REINFORCE++、Qwen 235B 教师），但实际试点用的是 Codex CLI 当教师、Qwen3.5-9B 当学生（只做了前向检查）。50 个 run、973 次教师调用、3800 万输入 token，筛出 HI 718 行 + GIA 108 行。Rubric 从 r1 改到 r6，演员指令从 r3 改到 r8。

**阶段 E（09-13 ～ 09-14）：做网页看数据。** `web_training.py` 和 `web/training*.js` 是最近改动的文件，用于在演示站里浏览 SFT 试点的轨迹。

## 5. 需要你亲自拍板的矛盾

这些不是清理能解决的，是设计或路线上的分叉，文档里同时存在多个答案。

**模型口径有五套。** README 主线是 OpenRouter 上的 Qwen3.8-27B；本地适配器是 Qwen3-14B-4bit；Smoke 是 Qwen3-0.6B/1.7B；训练方案是 Qwen3-8B；SFT 试点的学生是 Qwen3.5-9B、教师是 Codex CLI。训练方案还写着"不开付费模型 API"，而审查报告全部结果来自付费 API。你需要定一个推理口径和一个训练口径，其他全部归档。

**HI 到底是文本模型还是多模态模型。** 交接文档第 3、4 节说控制模型"只接收压缩后的文本或 JSON 观察"，多模态放工具侧；实现改成了 HI 直接收最多 8 张图片像素，并因此取消了 `visual_qa`/`audio_qa`。训练方案第 396 行又写"对它的视觉判断不作假设；如果实际调用的是文本 Qwen……"。这直接决定学生模型选型和 SFT 数据格式（826 行里有 2926 张附件图片），必须定下来。

**Harness-1 依赖要不要保留。** 运行必须指向一个不在仓库里的外部目录（`run_case.py` 里硬编码 `C:/Users/Zya/Documents/Codex/2026-07-23/plan-harness-1/work/harness-1`），但 `harness1.py` 只做了一次透传。如果论文不需要"基于 Harness-1"这个口径，整层可以去掉。

**消融清单不一致。** 交接文档 §24F 要求架构消融（去 GIA、去多轮、单 Harness、不分开训练、与 Harness-1 直接运行比较）；训练方案的四组比较全部是训练方法层面的（逐决策 SFT / +结果奖励 / +固定 rubric / 完整方案）。两份文档没有说明是替换还是叠加。

**"新任务快速适应"是研究问题的一半，却没有任何设计。** 如果你不打算做，研究问题的表述要改；如果打算做，它决定了保留集怎么划分，必须在训练前定。

**新颖性。** `相关工作与研究问题.md` 自己承认："仅采用状态对照、拆分两个模型或迭代 rubric 不足以构成新颖性"，ESBT、REVEAL、ARCO、Plan-and-Act、Divide and Cooperate 分别已覆盖各个组件。文档收窄后的可检验问题是："相同的真实局部报告，在不同全局问题下对应不同的必要补查与停止决定"——这需要的是离线 GIA 状态对照数据，而目前这类数据只有 23 行（GIA 总共 108 行，HI 有 718 行）。数据构造的重心放错了。

## 6. 建议的下一步（按顺序）

**第一周：止血。** 放开 `.gitignore` 白名单，把 `docs/`、`experiments/sft_data/*.{py,md,json}`、`corpus/*.jsonl` + manifest 全部提交；按第 4 节清掉 `.pytest-*`、`tmp/`、`outputs/`、`build/dist`；把三份根目录 md 移进 `docs/`，旧思路移进 `docs/archive/`。这一步做完，项目才有"存在于磁盘之外"的状态。

**第二周：定口径，写 DESIGN.md。** 对第 5 节的六个问题逐一做决定，然后从交接文档 §9–§23 提炼一份 ≤10 页的 `DESIGN.md`，写明当前定案 + 22 条否定清单 + 六个决定。README 压缩到 5KB 以内只讲怎么装怎么跑。以后任何新会话（无论是和谁）都先读 DESIGN.md 而不是 271KB 交接文档。

**第三周：把数据试点变成可信的。** 具体三件事：把 27 个仍用 r2 评审的 run（281 行）统一用 r6 重评；对 2–3 个短案例各跑 3 次相同配置，看 82.5 vs 87.5 这种分差是否只是采样噪声（目前所有对比都是 n=1）；按 `text_image_development.json` 的方式一次性抽够、冻结一个真正未见的保留集，此后不再用于改 rubric。

**第四周：训一次。** 在 340 行开发集上做一次 Qwen 学生的 LoRA SFT，在保留集上看是否有任何可测差异。这是从"数据构造试验"跨到"研究"的唯一门槛，所有文档都停在门口。就算结果是负的，也比现在有信息量。

之后再谈 RL、交替训练、消融。在第四步有结果之前，不要再往 `experiments/sft_data/` 里加新的案例、新的 rubric 版本或新的诊断脚本——那正是过去两周产生 40 个脚本和 25 个临时目录的方式。
