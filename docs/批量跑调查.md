# 批量跑调查（2026-09-28）

用法是：给一批案卷，一条命令跑出教师的调查记录（run），接着自动做核验和导出，得到训练数据。

```
案卷 experiments/sft_data/cases/*.json
  → 教师跑 bridge run（GIA 和 HI 都由教师决策）      runs/<数据集>_<编号>_<轮次>_<k>/
  → 生成 execution_links.json（runlog 需要它）
  → 记录成本                                        run_manifests/<轮次>.jsonl
  → （--then-verify）本地核验六步 + 导出              export/r0_bridgeN_…_compact_16k.local-<核验模型>/
```

代码在 `src/foren_searcher/datagen/run_cases.py`，服务器教师的接口在 `teacher.py`。

## 怎么跑

**先预览**：双击 `scripts\批量跑调查_预览.cmd`，只列出要跑的 run，不会真的跑。默认列的是 dev_train 划分的全部案卷。

**服务器（正式用法）**：先起两个 vLLM，教师在 8000 端口，核验模型在 8001 端口。然后：

```bash
bash scripts/run_cases_server.sh --limit 1     # 先试 1 个案例，看速度和成本
bash scripts/run_cases_server.sh               # dev_train 全部，跑完自动核验、导出
```

可以用环境变量改默认值：`TEACHER_ENDPOINT`、`JUDGE_ENDPOINT`、`JOBS`（同时跑几个 run，默认 2）、`ROUND`（轮次标签，默认 r0）。

**本机用 Codex 教师**：双击 `scripts\批量跑调查_Codex教师.cmd`，后面可以加 `--limit 1`。这条路走的是 ChatGPT 订阅额度，不走 OpenRouter，而且只能一个一个串行跑。

## 常用参数

| 参数 | 作用 |
|---|---|
| `--split dev_train` / `--split all` | 按划分筛案卷；`all` 表示不筛 |
| `--ids true:4124903 videosham_1028` | 只跑这些案例，写 case_id 或文件名都可以 |
| `--limit N` | 只跑前 N 个案例 |
| `--samples 4` | 每个案例跑 4 次，以后学生自采时用 |
| `--round r0` | 轮次标签，会写进 run 名和成本记录的文件名 |
| `--teacher endpoint` / `--teacher codex` | 服务器教师（默认），或本机 Codex |
| `--endpoint URL --model 名字` | 教师服务的地址和模型名；服务上只有一个模型时可以不写 `--model` |
| `--no-think` | 关掉教师思考（默认开着） |
| `--jobs K` | 同时跑 K 个 run |
| `--retry-failed` | 重跑中途断掉的 run：旧目录改名成 `.failed-<时间>` 留着，不删 |
| `--then-verify [--judge-endpoint URL]` | 跑完后对本批完成的 run 做核验和导出 |

已经跑完的 run（目录里有 result.json 和 execution_links.json）会自动跳过，所以中断之后直接重跑同一条命令即可。
每个 run 在独立的子进程里跑，一个出错不影响后面的。日志在 `experiments/sft_data/batch_logs/<run>.log`。

## 成本记录（对应总 TodoList 的"成本实测"）

每个 run 结束后，会往 `experiments/sft_data/run_manifests/<轮次>.jsonl` 追加一行，内容包括：

- 墙钟时间
- 教师调用次数（按 HI / GIA 分开）
- 失败的调用数
- 输入 / 输出 token
- 附图张数
- 最终决定和报告数

一批跑完后，屏幕上会打出每个 run 的平均值。成本实测时先跑 5 个案例（`--limit 5`），就能得到"单个案例要多少分钟、多少 token"。

## 和试点时期的区别

- 任务文字、媒体、来源策略都直接从案卷里读，不用再手写 selection 清单。
- 教师指令按角色分开：HI 调用用 `specs/hi@0.2.0/teacher_instruction.md`，GIA 调用用 `specs/gia@0.3.0/teacher_instruction.md`，用的规格和哈希都记进 run_config。
- 媒体按案卷里的顺序标成"材料 A / 材料 B"，和试点 run 一样（核验器靠这个标签区分两份材料）。
- 来源策略：
  - `unrestricted`：开网页搜索。
  - `provided_media`：不搜索。
  - `exclude_original`：按 `excluded_keys` 过滤搜索结果和打开的页面，存档地址也算。
  - `source_bound`：沿用试点的做法。
  - `date_cutoff`：**目前不生效**（属于阶段 04 环境固化），run_config 里会标出来。
- 检索还没有录制回放，同一案例重跑时搜索结果可能不一样（阶段 04）。
