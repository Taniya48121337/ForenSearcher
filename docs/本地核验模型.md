# 本地核验模型（2026-09-28 起默认，不再走 OpenRouter）

核验链路（三层核验 → 单元核验 → 召回校准 → 导出 → processor 核对）现在默认连一个**本地 OpenAI 兼容服务**，不花 API 的钱。
代码只认 `http://地址:端口/v1` 这种接口，所以 5090 和服务器用的是同一套代码，只换地址和模型名。

## 一、起服务

### 5090（Windows）

任选一种，能起一个 `/v1` 接口就行。

**A. WSL2 + vLLM（推荐，跟服务器同一套）**

```bash
# WSL 的 Ubuntu 里；需要支持 RTX 50 系（Blackwell）的较新 vLLM
pip install -U vllm
vllm serve /mnt/e/Codex/workspaces/ChatGPT/ForenSearcher/.models/Qwen3.5-9B \
    --served-model-name qwen3.5-9b --max-model-len 16384 --gpu-memory-utilization 0.90 --port 8000 \
    --limit-mm-per-prompt '{"image": 8}'
```

Windows 这边直接访问 `http://127.0.0.1:8000/v1`（WSL 默认会把 localhost 转发过来）。

**B. LM Studio / Ollama（不装 WSL）**

- LM Studio：下载一个**带视觉**的模型，打开 Developer → Start Server，地址是 `http://127.0.0.1:1234/v1`。
- Ollama：`ollama serve` 之后地址是 `http://127.0.0.1:11434/v1`。

用 B 时，跑脚本要加 `--endpoint http://127.0.0.1:1234/v1`，或者先 `set FOREN_JUDGE_ENDPOINT=http://127.0.0.1:1234/v1`。

**模型必须能看图**：核验里约四成调用带帧 / 截图，纯文本模型会在这些调用上报错，结果会变成 pending。

### 服务器（8×A100）

```bash
vllm serve /data/models/<核验模型> --served-model-name <名字> --max-model-len 32768 --port 8001 \
    --limit-mm-per-prompt '{"image": 8}'
```

跑的时候加 `--endpoint http://服务器IP:8001/v1 --model <名字>`。

服务器上教师占 8000 端口，核验用别的端口和别的卡。按设计，核验模型要与教师（Qwen3.5-122B）分开；参考核验器 verifier_ref 还要跟两者都不同家族。

## 二、跑

按顺序双击 `scripts\` 下的三个文件：

1. `检查本地核验服务.cmd`：确认服务在、列出模型，再让模型试答一道小题。能答出 JSON 就可以往下走。
2. `本地核验冒烟_1个run.cmd`：只跑 `true_4124903_r1` 一个 run，六步全走。看速度，也看判得像不像话。
3. `补全核验_本机跑.cmd`：12 个 bridge run 全量跑。

常用参数（加在 `.cmd` 后面，或者直接调 `python scripts\complete_verify_local.py`）：

| 参数 | 作用 |
|---|---|
| `--endpoint URL` | 服务地址，默认 `http://127.0.0.1:8000/v1` |
| `--model 名字` | 服务上只有一个模型时可以省略 |
| `--think` | 打开模型思考：更准，但慢几倍，默认关 |
| `--runs a b` | 只跑这几个 run |
| `--from N --to M` | 只跑第 N 到第 M 步 |
| `--judge openrouter` | 付费 API。要加 `--yes-spend`，或者在提示时手动输入 yes |

并发数用 `set FOREN_JUDGE_CONCURRENCY=8` 调，默认 4。vLLM 可以开大一些；LM Studio 基本是一条一条处理，开大没用。

## 三、产物放在哪

每个产物都带模型标签，例如用 `qwen3.5-9b` 跑出来的是：

- `experiments\sft_data\verdicts_r0_judged.local-qwen3.5-9b.jsonl`
- `experiments\sft_data\verdicts_units_judged.local-qwen3.5-9b.jsonl`
- `experiments\sft_data\calibration\recall_r0.local-qwen3.5-9b.json`
- `experiments\sft_data\export\r0_bridge12_hi@0.2.0_gia@0.3.0_compact_16k.local-qwen3.5-9b\`
- 缓存：`experiments\sft_data\verify_cache.local-qwen3.5-9b.jsonl`

换模型（比如从 5090 小模型换到服务器大模型）会生成另一套文件，互不覆盖，缓存也不会串用。
OpenRouter 时期不带标签的文件（`verdicts_r0_judged.jsonl`、`verify_cache.jsonl`、`export\r0_bridge12_…_compact_16k`）原样保留。

## 四、注意

- 5090 上的小模型只用来**验证链路能跑通**。它的判定不能拿来当正式训练数据的入选依据，也不能和 OpenRouter qwen3.8-27b 的数字直接比。正式数据用服务器上的核验模型重跑。
- Qwen3.5-9B 是学生底座，拿它当核验模型只适合冒烟。
