## 一、术语定稿：循环轮次 vs 数据批次

**两个维度，名字互不借用：**

- **循环轮次**（训练 → 部署学生 → 采数据 → 再训练的那个"轮"）：第 0 轮 = 第一次 SFT。第 0 轮的训练集（多批合包后）叫 **sft0**；第 k 轮训练集 **sft<k>**；第 k 轮训出的模型 **m<k>**（`hi-m0` / `gia-m0`）。
- **数据批次**（《可训性评估》叫"数据批次 / 流水线版本"：一次冻结 + 全量跑 + 门 + 包，用 `walker_run --round`、`specs/<x>_freeze.json`、tag `<x>-frozen` 标识）：r0a、r0g、r1、g1、g2……批次名只说"哪一批"，不说"第几轮"。**`r1` 是批次名，不是"循环第 1 轮"**（"r1 预演"时学生一步没训）。
- **进循环后的轮次**：《可训性评估》〇节给了 `loop1` 或 `r2` 两个候选，**建议用 `loop1`、`loop2`…**——`r2` 在执行计划里已经是"r2 待办"（下一版流水线 / 数据批次）的名字，再拿来当轮次就把本节要拆开的歧义又造回来了。训练集 `sft<k>`、模型 `m<k>`（`hi-m0` / `gia-m0`）与轮次同号。
- **run 的轮次标签（round tag）是第三样东西**：walker 按 `round.startswith("r1")` 切 r1 行为（memory 与 g1 报告都记过：round 叫 `g1` 会静默走 r0 规格与检索策略）。所以批次 g1 / g2 的 round tag 是 `r1g1` / `r1g2`。进循环后新批次的 round tag 也必须保持 walker 策略前缀（例如 loop1 的第一批 round tag 写成 `r1loop1a`），直到 walker 换策略版本；这条是代码约束，《可训性评估》没提，补在这里。

## 二、教学矩阵的"可学标准"（r1 基准）

基准：`experiments/sft_data/export/r1_134runs-6a8cb9f4_…/hi_accepted.jsonl`（1322 行）+ `gia_accepted.jsonl`（102 行）。脚本 `claude/_longtail_work/branch_tables.py`（→ `branch_tables.json`）、`tables_md.py`（→ `tables.md`）。
档：**可学** = accepted 行 ≥ 15 且来自 ≥ 5 个不同 case_id；**薄** = 1–14 行（或 ≥ 15 行但 < 5 案例）；**零·期望 ≥ 1** = 0 行且覆盖表 `MATRIX` 最少次数 > 0、不在允许为零 / 按设计为零清单；**零·允许为零** = 0 行且属于下面后三类之一。
覆盖表口径按《walker_wk8》6–7 节，**"期望 ≥ 1"与"条件触发"是两类，不混**：
- **期望 ≥ 1**（MATRIX 最少次数 > 0）：有一类案例会自然触发，低于最少次数算"不够"。《可训性评估》二节的最低可学标准（≥ 15 行、≥ 5 案例）**只对这一类**是要求；达不到的要么补案例、要么挪进允许为零并写理由。
- **条件触发**（MATRIX 最少次数 = 0：PDF 扫描件、续读、image→video、页面链接的视频、打开已知网址、GIA 第 2 轮查记忆）：触发条件取决于数据，本批 0 行写"条件未出现"，**不算缺口**；有行但薄也不算缺口（表里标"薄·条件触发"）。
- **C4 允许为零清单**（`ALLOWED_ZERO`，《export质量门》二节：A 族链路、get_frames pages、SEARCH image→video、compare_media audio）与**按设计为零**（`BY_DESIGN_ZERO`：GIA 第 1 轮派工、GIA 记忆动作）：门上 0 行不算不过。get_frames pages、image→video 同时是条件触发与 C4 清单。
最后一列是合包后的行 / 案例，供对照（统计时 sft0 = r1 + g1 + r0 包里 r1 没有的 4 个 L 案例；按五节 ① 的结论 r0 包整体不进，只差这 32 行 L，其中 image→text 4 行）。

### 3. sample_weight = 3.0 的 413 行是怎么来的（读 `datagen/export.py`，只读）

- 权重分两段算。**`decide_row`**：HI 动作行 `weight = min(WEIGHT_CAP=3.0, 1.0 + clue_gain)`；HI 报告行 `report_weight`：COMPLETED 且核验无错误 3.0（`REPORT_COMPLETED_CLEAN`）、COMPLETED 带错误 2.0、INCOMPLETE 写明缺什么 2.0、空泛 1.0；GIA 答案 1.0（recovered_from_tainted 2.0），plan 1.0。**`adjust_action_weights`**（manifest 的 `weight_adjustments`）只往下乘：READ_RECORD / QUERY_MEMORY 且 clue_gain = 0 ×0.5（`memory_action_gain0`，41 行）；同一工作区连续 ≥ 4 步同一动作，中间的 ×0.5（`repetitive_run_middle`，259 行）。之后 `apply_dataset_share_caps`（videosham 份额 5.4% < 0.34，没触发，manifest `dataset_share_caps = {}`）。
- `clue_gain`（`verify/hindsight.py`）= 这一步**新拿到的有用证据数**（acquired：产出了最终撑住结论的 E，U = 案卷 required_evidence 匹配到的 E ∪ 干净 Finding 引用的 E）+ **第一次读到其正文**（observed，只 READ_RECORD）+ **读的这一页落着核验器摘出的引语**（quote_page）。一次 SEARCH 产出很多被引用的 E 时 gain 可以到 14–18（413 行里 gain=2 的 219 行，≥ 10 的 78 行）。
- 413 = **386 行动作**（clue_gain ≥ 2、没有被降权：READ_RECORD text 196、SEARCH image→image 62、SEARCH text→text 62、get_frames times_s 46、SEARCH text→image 17、times_s+box 2、open video 1）+ **27 行报告**（COMPLETED 且无错误）。也就是说 **3.0 不是"放大"，是 1 + gain 被上限截断**；占权重和的 46%（1239 / 2672）。READ_RECORD text 的 196 行是头部最大的一块（见四节）。

### c. 结构性教不到的（判断、派工、收工）

walker 是规则程序：第 1 轮派工照抄题目（134 / 134 被 C3 held）、第 2 轮派不派由 G2 规则按缺口类型定、什么时候交报告 / FINISH 由剩余轮次与 G3 规则定、报告 status 由 S4 写但"查到什么程度算完"是 walker 的链路决定的。学生从这些行里学到的是**规则的表面**——同一个决策边界复制得再多，也只是同一条边界；而且这些决策点的输入状态都是 walker 自己走出来的，学生部署时自己走出的状态（漏读、早停、多搜）一次都没见过，加 walker 数据对此无效。这正是《设计总览》四节 A（"真正的判断留给循环""GIA 派工和收工等于抄题 + FINISH"）与《可训性评估》二节第 3 类。设计里已有、还没启用的通道和各自前提（《设计总览》四节 A / C14、执行计划 S6、`docs/04_训练与数据/sft数据构造方法v2_20260921.md` 四节来源 B–E、`RSI融入方案_20260924.md`）：
