### g1 包里 `--teacher-override` 实际记了什么

- **包级（`g1_pack.json`）**：`teacher_override = {file: specs/g1_teacher.json, sha256: 96abd632…9594, slots: [S0–S3], base_freeze: specs/r1_freeze.json}`、`teacher = g1_teacher.json`；核对项 `teacher`（逐槽：S0–S5 全是 gpt-6-astra × 146 run）与 `teacher_override`（146/146 个 run_config 的文件名 / sha256 / base_freeze 一致）；`freeze/` 里同时有 r1_freeze.json 与 g1_teacher.json。
- **run 级（`provenance/runs.jsonl`）**：每个 run 有 `slot_models`（S0–S5）、`slot_backends`（S0–S3 = codex_low、S4/S5 = strong）、`teacher = g1_teacher.json`、`freeze_id = r1`、`freeze_ok`。
- **行级（`data/*.jsonl` 的 metadata）**：`origin = "A"`（**不是 g1**，导出没给 `--origin-tag`）、`source_kind = "A"`、`teacher_model / slot_teacher / terminal_teacher = gpt-6-astra`、`row_slot_models`（本行用到的槽 → 模型）；**没有 `teacher_source` 字段**。
- **导出 manifest**：`freeze_file = specs/r0_freeze.json`、`require_freeze = false`、`origin_tag = null`——与 r1 同一根因（长尾五节 ③：`complete_verify_local.freeze_applies` 写死 r0_freeze）。
- 结论：**教师来源逐槽可还原**（行的 slot_teacher + runs.jsonl 的 slot_backends），**来源批次（origin）不全**。两个选法：(a) 不重打 g1，sft0 合包时逐行写 `teacher_source`（按 runs.jsonl 逐槽判，不只看 S0）与 `batch = g1`，报告写明 g1 与 ⑥ 的差异；(b) 用现成判定文件只重跑 g1 的 export（`--origin-tag g1 --freeze-file specs/g1_freeze.json --require-freeze`，不再核验、不花 Claude 额度）再重打包。
