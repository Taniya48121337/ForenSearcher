## 事故与教训

1. **GIA 被派到不存在的 GPU（事故①，10-20 00:29）**：`resume.sh` 在 tmux 里起 `13_train_queue.sh`，tmux 不继承调用方的 `FS_PROFILE=vast1` → 用了 8 卡默认槽位 `0;1;2;3`；
   13 的 GPU 检查遇到 "No devices were found" 只报整数比较错、没停 → GIA 以 `CUDA_VISIBLE_DEVICES=1` 启动，两分钟后 Triton "0 active drivers" 退出。HI 不受影响，没有并行训练。
   修（`a9235f6`）：每个 tmux 命令显式带 `FS_PROFILE=vast1 FS_LOG_DIR`；13 遇到查不到的 GPU 直接失败。**教训**：tmux 命令要自带环境，不能靠调用方 export。
2. **第二台被误销毁（事故②，10-20 02:13–02:24）**：GIA s1 在第二台以 mp=on 训到 checkpoint-50（02:12:05，HF 已核）后实例被销毁（负责人已确认是误操作）。
   损失 = checkpoint-50 之后约 10 分钟的步数；GIA 在第一台从 HF 的 checkpoint-50 续训（02:27:43）。**教训**：checkpoint 每 50 步 + 自动上传 HF + 续训身份核对这套救了这次；
   销毁前必须有"该机上没有在训的任务"的确认（第一台销毁时就是这么做的）。
3. GIA 之前还在第二台重启过两次（不是事故、是负责人的决定）：mp=off 那次第 6 步 kill；中转手写配置那次第 4 步 kill（负责人要求只用入库配置），都没有 checkpoint。
4. **code-only 副本漏文件**：只推了 `experiments/sft_data/*.json`，tag 里的 `oracle_generator.py`（测试要）与 `source_policy.py`（exclude_original 案例要）没推 → dev_eval 4 个 run 1 s 失败。
   **教训**：用逐文件核对（`server/code_parity.py`）而不是挑目录；lock 前做了全量核对。
5. **CPU 争抢 / 线程爆炸**：12 个评测进程各开满 128 核的 onnxruntime / torch / BLAS 线程池 → 单 run 40–50 min、一个 run FINISH 后 35 min 不退出。线程上限后单 run 17–28 min。
6. **看门狗 30 min 太紧**：杀了 7 个正常推进的 run；改 60 min 后重排全部完成。训后负责人定 90 min（并发更高）。
7. **热降频**：第一台训练时 93% 时间 SW Thermal Slowdown，~1 ms/token 的主因；HI 因此迁第三台。
8. 自己的命令误伤自己：`pkill -f <pattern>` 匹配到 ssh 远端执行这条命令的 bash（两次：一次杀掉、一次 SIGSTOP 挂住）。**教训**：远端用 `pkill -f "datagen[.]run_cases"` 这类不自匹配的写法。
9. behavior_metrics 的 Wilson 区间在 k > n 时崩（报告项 compare_rate_of_acquired，tag 版本就有）：修成 k > n 不算 CI，四个登记指标不变、重新登记 hash。
10. flash-attn2 在 Qwen3.5（transformers 5.3）上 loss 全 nan：没深挖，记 loop1。

### 断点续训（`training/sft_lora.py`）

- `--save-every 50`：每 50 次更新在 `output_dir/checkpoint-<step>/` 存 adapter + 优化器状态 + 本 epoch 的打乱顺序与位置 + Python / torch CPU / CUDA RNG + 历史 + 身份
  （配置去掉输出位置 / 存盘频率 + 训练行 hash）；先写 `.tmp-checkpoint-*`、写完 `COMPLETE` 再改名；只留最近 2 个（`keep_checkpoints`）。原来的 `save_every` 只存 adapter 到 `step_<N>/`（没有地方读它）。
- `--resume`：从最近一个完整 checkpoint 接着训，身份不一致就停；没有 checkpoint 就从头训。
- 等价性（本机 CPU、`--smoke-tiny`）：一口气训完 vs 停在第 1 步 + `--resume`，**final adapter 32 个张量逐位相同**、每步 loss 相同；两种情形都测了：epoch 中间停、
  epoch 末尾余数步停（续训从下一次打乱开始，`epoch_1/` 照常写出）。`--stop-at-step N` 是试跑用的（存完第 N 步就停）。
- `server/jobs/vast1_sft0_s{1,2}.txt` 每行加 `--save-every 50 --resume`。HI 844 步 → 16 个 checkpoint，GIA 207 步 → 4 个。
