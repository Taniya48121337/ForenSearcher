# g3a 金标标注指南（2026-10-19，g3 目标分支专项）

20 条：**15 条 Finding**（F001–F015）+ **5 条答案**（A001–A005），全部来自 g3（轮次 `r1g3`，80 个 run：A 族 17〔自剪删段 FMNV 6、
GroundLie360 1、FMNV CE 类 fv 10〕、V9 30、QVHighlights 15、C 族 18；S0–S5 全走 Codex，冻结口径 `specs/g1_freeze.json`；verifier@0.4.0，
`verdicts_r1g3_judged…80runs-be437e21.jsonl` / `verdicts_units_r1g3_judged…`）。
格式与 r1a / g1a / g2a 相同：`items.json`（证据正文上限 8000 字）、`strata.json`（**标注时不要打开**）、`media/`、`标注.html`。
复算：`python scripts/_gold_eval.py --batch experiments/sft_data/gold_set/g3a --labels labels_<标注人>.json`。

## 这批查什么

g3 按收益补学生学不到的分支：A 族找原片（SEARCH text→video 及其后的 compare_media / 取帧 / 查日期）、HI QUERY_MEMORY（V9 变体：卡片 6、
历史 4，交报告前把掉出视图的证据查回来）、QVHighlights 定位（INSPECT locate / Q 族）。Finding 按"它来自哪种目标分支"抽，看这些分支写出的
结论是否被所引证据支持。

## 怎么抽的（标注人可以知道，但不要据此猜某一条是否被标错）

`python scripts/g3/g3_gold.py`（包一层 `_gold_sample.py`，不改它）：`--findings 15 --new-action-quota 15 --oversample-flagged --answers 5
--answers-balanced --plans 0 --seed 20261019g3 --round-prefix r1g3 --only-cases walker_r1g3_done_cases.json`，新动作三类换成 g3 的：
A_video（A 族 Finding 引了 compare_media 记录）5、locate（QVHighlights 的 Finding）5、query_memory（V9 run 里真发过
Q1_query_memory_before_report 的 Finding）5；类内核验器标 major/critical 的先取（15 条里 9 条标错），每 run 至多 1 条。
答案 5 条只从 A 族 run 里抽（unit 判定先筛成 A 族答案单元），positive / negative 平衡。

## Finding：判"所引证据是否支持这条陈述"

`main`：full / partial / none / cannot_tell，口径同 r1a / g1a / g2a 指南。按类多看一眼：

1. **A_video**：compare_media 报的对应段 / 删掉的区间，陈述照抄得对不对（两侧时间、"B x–y s 在 A z s 处被略去"）；"找到的就是原片"有没有
   超出比对能证明的（找到的可能是另一份转载——GroundLie360 那条冒烟时就找到了比案卷原定更像原片的上传）。fv 类（FMNV CE，数据集作者删段）
   **没有被删区间 GT**，只看陈述与比对记录是否一致，不按区间对错判。
2. **locate**：定位的起止秒数是否落在所引帧 / 镜头表能支持的范围内；"边界只能夹在采样帧之间"如实写了不确定范围的不算错；把没看过的区间
   说成"不符合"算超出证据。
3. **query_memory**：查回来的证据（QUERY_MEMORY 的结果）与陈述引用的是不是同一份；陈述有没有把查回来的摘要说得比原记录更确定。

## 答案：判"答案是否只说了证据支持的内容"

A 族答案：原片地址 / 标题是否与所引报告一致；差异描述（删掉 / 替换的段）是否与比对记录一致；没找到原片时有没有如实说"没找到"而不是编一个来源。
