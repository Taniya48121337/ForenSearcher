# 金标集 v1 标注说明（2026-09-28）

这一批用来量核验器准不准。核验器会判断三件事：Finding 是否被它引用的证据支持、最终答案能不能接受、每轮派的任务是否合理。人工给出独立判断，再和核验器的结论对照。

## 怎么标

1. 双击本目录的 `标注.html`，用浏览器打开。不需要联网。
2. 在右上角填写标注人（姓名缩写）。
3. 逐条标注：
   - 快捷键：`1`–`4` 选主判断，`N` 或 `→` 下一条，`P` 或 `←` 上一条。
   - 进度自动保存在这台电脑的浏览器里，关掉页面再打开还在。
4. 标完点"导出标注"，下载 `labels_<缩写>.json`，把它放进本目录。
5. 换电脑继续标：先用"导入"载入之前导出的文件。

共 80 条：
- F001–F060：Finding
- A001–A012：最终答案
- P001–P008：派工计划

页面不显示核验器的判断，以免先入为主。

## 判断口径

**Finding**：只看它自己引用的证据，不要用外部知识补。
- **完全支持**：结论的每个实质断言都能在所引证据的原文或画面里找到。
- **部分支持**：大体对，但有一部分超出了证据，例如更精确的数字、更强的因果、把"候选"说成"确认"，或把来源的说法当成事实。请把超出的片段照抄到文本框里。
- **不支持**：核心断言在所引证据里找不到，或者与证据矛盾。
- **无法判断**：证据残缺，或图片看不清。

**最终答案**：对照案卷要求逐条勾选"覆盖/未覆盖"，再给整体判断。
- 有小问题但结论和主要依据都成立，选"有小问题，仍可接受"。
- 结论方向错、关键断言没有依据、证据明显不足就结束，选"不可接受"。

**派工计划**：每个任务是否针对"此前报告还没解决、而且会影响答案"的缺口。
- 同一轮里的任务相互重叠、题面把没证实的事写成前提、依赖同轮其他任务的结果，都算问题。

## 标完之后

```
python scripts\_gold_eval.py --batch experiments\sft_data\gold_set\v1 --labels labels_<缩写>.json
```

- 输出核验器的精确率、召回、κ 和每类条目的人工用时。
- 加 `--report-verdicts` 和 `--unit-verdicts` 可以换一份判定文件对照，例如本地 gemma 核验的结果。
- 有两位标注人时，把两份 labels 一起传进去，会另外算标注人之间的一致性。

## 抽样方式

依据：
- Finding：`verdicts_r0_judged.jsonl`（09-24 的 OpenRouter 核验）。
- 答案和计划：`verdicts_units_judged.jsonl`。

Finding 按"核验器是否标了 major/critical 错误"分两层，各抽 30 条；层内按数据集轮转，每个 run 最多 3 条。答案单元 12 条全部入选。计划单元抽 8 条，其中 negative 全取。随机种子为 20260928，可以复现。抽样层和核验器当时的结论记在 `strata.json`，标注时不要打开它。
